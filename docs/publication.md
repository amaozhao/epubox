# 正文恢复、出版与命令行交接

日期：2026-10-06\
范围：T17—T19 的正文日志、原子 EPUB 出版和现有 CLI 接线。\
前置接口：[workflow.md](workflow.md)。全链路真实验收仍属于 T20。

## 1. 正文阶段日志

`BodyJournal` 接入 T16 已有 workflow 的 `save` 回调，没有建立第二套翻译执行器。它以物理回读通过的 `ReadySession` 为身份根，只接受当前 `prepared.json`、member 清单和冻结配置拥有的记录。

每个 member 的当前结果继续保存在 `results/<item_id>.json`。保存时会重新核对 item、来源范围、术语、上下文和 ready 身份；初译可以推进到校对结果，已经终态的 reviewed/needs_attention 记录不能被旧稿回滚。重复写入完全相同的记录是幂等操作。

正文请求继续使用已有 `requests/*.json`、attempt 和 `responses/<stage>/<request_id>/<attempt_id>.json` 格式：

1. 请求清单和预留 attempt 在模型调用前保存。
2. 模型响应及实际 usage 在 attempt 完成状态前保存。
3. 重启时先按相同 request/wire 身份回放已保存响应，再决定是否调用模型。
4. 已完成初译从保存的当前稿继续校对；已完成校对不重新请求。
5. 累计 HTTP 次数和 token 用量来自保存的 attempts，不因恢复而清零。

运行时只从 ready 计划读取冻结的模型、并发、输入/输出限制和运行请求上限。传入的模型身份与冻结值不一致时拒绝继续；来源、原子归属、词表、提示或 ready 身份变化也不能静默复用正文结果。当前实现不提供旧正文 JSON 的通用转换器。

## 2. 完整父项与派生导航

虚拟 piece 只用于模型请求和逐阶段保存。出版前，`parent_targets(require_complete=True)` 要求一个原始父项的所有兄弟 member 都是 reviewed，再按稳定 piece 顺序合并并重新验证父项完整标记清单。

派生导航不增加模型请求。它只在来源标题父项已经形成合法完整目标后，使用既有导航投影规则生成目标。缺少兄弟、未完成校对、父项归属不一致或派生来源不完整都会阻止出版。

## 3. 原子 EPUB 出版

`publish_atomic(store, output_path, checker, overwrite=False)` 保持既有字典返回形状：

```text
{
  "path": 最终路径,
  "sha256": 最终文件哈希,
  "verification": 校验记录,
  "publish": 发布事务记录
}
```

它不引入新的 PublishedBook schema。流程如下：

1. 回读 ready、全部 reviewed parent target 和不可变 `source.epub`。
2. 要求目标集合与原始 inventory 完全一致，不允许漏项或额外项。
3. 通过 `fill_resource` 按已验证的原字节区间回填正文、属性和导航目标。
4. 只对白名单语言字段做字节局部更新：XHTML 根元素的 `lang`/`xml:lang`，以及 OPF 主 `dc:language`。
5. 从源快照建立候选 EPUB；图片、CSS、JS、字体及其他未替换资源复制原始内容。
6. 校验资源清单、EPUB 版本、OPF 路径、spine、字体混淆、文档结构、内部引用、语言字段、目标证据和 EPUBCheck 结果。
7. 再次核对源哈希和正文结果没有变化，然后写发布意图并原子提交到目标路径。

默认目标位于原 EPUB 旁，名称为 `<stem>-cn.epub`。源快照、准备记录或它们的硬链接/别名不能作为输出；已有目标只有显式 `overwrite` 才能替换。候选校验失败时不会覆盖旧成品。`publish.json` 绑定计划指纹、每个目标的版本向量、目标路径和目标哈希，因此进程在提交附近中断后可以核对并恢复同一次发布。

## 4. CLI 接线

现有三个命令保持不变：

- `translate`：准备、正文初译、校对、修订、校验和出版。
- `resume`：只使用工作目录内冻结的源快照和配置继续。
- `plan-resume`：只读判断下一步，不发模型请求，也不修改记录。

新任务使用原子 strategy、输入预算 v2 和输出预算 v4（见第 8 节）。输出预算 v4 完整预留配置的 provider 输出额度，并为完整响应估算加入分词差异余量；估算超过额度时在 HTTP 前拒绝请求。既有输出预算 v2 的身份保持不变，未完成的真实接口任务暂停，不静默改写预算或重跑。`--limit` 表示单个原子源片段的最大 token 数；显式参数优先于 `EPUB_CHUNK_MAX_TOKENS`，两者都没有时使用已定义默认值。该值与模型上下文、最大输入、最大输出及 HTTP 次数是不同限制。任务建立后，恢复继续使用落盘的 `max_source_tokens`，不会因后来修改环境变量而重切已完成内容。

重复执行同一本书会先查找匹配的冻结任务。有效 `prepared.json` 进入正文恢复；有效 `publish.json` 和成品哈希匹配时直接返回已完成结果。默认工作资料位于原书旁的同名目录，使用 `source/` 和 `state.json`，最终文件仍为原名加 `-cn.epub`。

2026-10-07：直接重复 `translate <原书路径>`，无需恢复参数。`active.json` 绑定原书哈希、快照哈希和同名目录内的冻结任务；查找时重新校验文件身份，缺失检查点或符号链接不能建立空白任务。仅无附加参数的自动续传会回放缓存并重新开放未完成的 v3 正文项，每次命令只开放一轮；已校对项和累计请求次数保留。手动 `resume` 仍保留显式重试规则。用户显式指定的配置若与冻结任务冲突，会在请求和写入前拒绝。

使用修复副本的任务在 `source.json` 的 `aliases` 中同时绑定用户原书的绝对路径、哈希和 inode；缺少绑定时自动续传拒绝继续。出版检查保护主来源和全部别名路径及硬链接，不能覆盖用户原书。

准备阶段立即报告阶段计数。正文每批报告 request ID、结果状态、完成单元、初译/校对项、待处理项、耗时、正文估算、输入估算、输入/输出预留、实际累计 token 和 HTTP 次数。估算、预留和服务端实际 usage 是不同指标。

## 6. 源书合规问题基线（2026-10-07）

按用户最新要求，EPUBCheck 的 ERROR/FATAL 不再直接阻止可解析源书进入翻译。ZIP 安全、必需资源、OPF/spine、支持范围和 XML 解析检查仍保留；检查器不可用、超时、运行失败或诊断无法定位时明确报错。

使用当前检查器的完整文本诊断，按 severity、错误代码、资源、稳定元素路径、QName、消息和重复次数比较。行列号仅用于将诊断绑定到元素：Java 列号按 UTF-16 单元转换，翻译造成的位置变化不构成新问题。无法绑定的二进制/资源级诊断仅允许在对应资源字节不变时继承；不按全书错误总数判断。

源诊断展示数据保存到现有 `report.json` 的 `source_validation`，准备阶段显示摘要与报告路径。该报告是可替换展示数据，不作为冻结计划或恢复权威。出版从不可变快照重新检查源书，并检查候选成品；只允许原有 EPUBCheck 问题和原有内部引用诊断，新增问题拒绝发布。资源、结构、回填覆盖和语言检查仍保留。

继承问题的成品在 `publish.json.verification.baseline` 保存源/目标哈希、原始源诊断和继承数量；实际 `verification.epubcheck.passed` 保持 false。命令行明确显示原书遗留问题，不声称完全通过 EPUBCheck。零错误记录的格式和恢复路径保持兼容。

原子及旧流程的已完成任务恢复均接入同一基线验证。对保留错误的成品，恢复会重新运行安全配置的本地检查器并核对基线，不执行 JSON 中保存的命令，不发模型请求。检查器变化或不可用可能阻止这类成品的恢复验证；已通过 EPUBCheck 的旧成品保持原来的本地快速恢复。

## 7. 单 JSON 工作目录（已实施）

用户进一步要求每本书仅保留解压内容和一个进度 JSON。目标布局为原书旁的 `<原书名>/source/` 与 `<原书名>/state.json`，最终 `<原书名>-cn.epub` 仍在原书旁。

`state.json` 合并源身份、冻结配置、术语、chunk/位置/占位符映射、初译、review 结果、当前阶段、累计用量和必要失败诊断。无需将每个请求、响应、member、batch 或结果独立物化为文件，也不保留哈希/run 层级或重复的源 ZIP。JSON 采用原子替换，中断后通过原书身份和已保存的阶段继续。

默认普通命令现已采用上述布局。既有 RunStore/workflow 的语义接口保留，逻辑记录通过统一读写/枚举/统计接口保存在 state.json；没有第二套翻译执行器。JSON 保存原记录精确 UTF-8 字节和版本戳，原子替换并 fsync；缓存遇到外部修改会刷新并失效校验证据。进程锁保存在系统临时目录，工作目录不生成锁文件或记录子目录。

源 EPUB 作为按哈希验证的只读原文件引用，不再复制 source.epub；source/ 安全解压并保留 ZIP 资源字节。打包从解压资源和已校验回填结果读取内容，保留原 ZIP 条目元数据，未修改资源仍与原文件逐字节核对。

匹配的旧任务会逐字节导入状态并验证原书、准备数据及每条记录，之后才清理已迁移的旧运行目录。来源修复副本与用户原书不同的历史任务继续沿用旧路径，不能丢失其来源证据。只有尚未派发请求、无手工词表且因旧预算阻塞的本地准备可以原子重建；保留冻结偏好，仅更新预算/提取算法。已保存的模型结果不会因此重跑。

迁移header、记录和完成标记一起原子提交，中断后先恢复资源解压/验证/清理再进入执行。每个模型响应先持久化，再将其全部兄弟结果通过同步批量事务一次提交；事务不跨越模型调用或异步回调，失败回滚，不重发已缓存响应。

## 8. 占位符预算及导航修复

新任务冻结输出预算 v4、原子提取器 atomic-2；v2/v3 与 atomic-1 按旧算法回放。v4 的 S 限制只计可翻译文本，完整请求 I 仍计入所有标记/提示/上下文。R 完整计入响应 JSON、每个保留标记一次、文本膨胀及分词余量，再预留配置的输出 cap；单纯结构标记不乘译文膨胀率。输入、输出和模型上下文硬上限没有放宽。

EPUB toc/page-list/landmarks 中的锚点标签按导航字段提取，锁定包装结构；普通正文 p/table/em/i/ul/ol 的不可拆规则保留。可匹配的导航从正文标题派生，未匹配标签仍进入翻译；没有漏掉目录标签。

派生项保存的blocked_dependency状态不携带模型translation_frame。恢复必须精确匹配冻结依赖记录；普通初译/校对项仍要求规范frame和实际持久响应证据。依赖标题完成后，派生目标在回填时生成，不伪造模型响应或额外请求。
