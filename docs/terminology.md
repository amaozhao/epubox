# 原子预检与术语阶段交接

日期：2026-10-06\
范围：T08、T11、T12\
后续任务：T13—T20

本阶段完成付费前原子预检、术语批量执行与恢复、候选证据校验、冲突核对和词表冻结。生产 P1—P4 管线与 CLI 接线仍属于 T15；本文不声明真实书籍已经通过新流程翻译或发布。

## 1. T08 原子预检凭据

[preflight.py](../engine/services/preflight.py) 从冻结的 `source.epub`、`preparation.json` 和全部准备资源重建原子清单。它先验证恒等目标能够按原字节回填，再检查每个不可拆原子或安全虚拟分段的四类预算：

- S：正文源 token 上限。
- I：完整输入 token 上限。
- R：输入、输出预留和安全边距之和不能超过模型上下文。
- M：保守输出需求不能超过冻结输出上限。

`p`、`table`、`em`、`i`、`ul`、`ol` 等硬原子不会为了通过预算而拆开。普通虚拟块只能使用 T05 已登记的安全源切点。任一阻断都会保留诊断和源位置，但不会产生可用于派发的通过凭据。

通过结果保存在 `checks/preflight.json`，原子清单保存在 `inventories/*.json`。凭据绑定：

- 源快照和准备记录身份。
- 全部资源路径、原始字节、映射及原子清单哈希。
- 模型、chunk 上限和预算算法版本。
- 预检分段、输入输出需求及最终通过状态。

`require_preflight()` 不信任 JSON 中单独的 `passed` 字段。它使用当前冻结输入重新计算并比较结果；源、配置、映射、原子或模型变化都会使旧凭据失效。

## 2. T11 请求投影与 token 边界

[runner.py](../engine/services/terms/runner.py) 继续一次请求合并多个提取项。主证据完整保留；只读上下文在整批根级共享，最多选择同一文档、同一内容通道中最近的两份前文，排除本批 primary 范围和未来文本。每份上下文最多 400 个字符；这是上下文片段上限，不是正文或整个请求上限。

输入预算 v2 对实际要发送的完整消息计数，包括固定提示、JSON 包装、主证据、上下文、用户规则和重试反馈。计量使用本地 tokenizer，并在计数上增加 50% 预留和 256 tokens 包装余量。派发还必须同时满足：

```text
估算输入 <= min(50000, 冻结输入上限)
冻结输出预留 <= 冻结输出上限
估算输入 + 输出预留 + 256 <= 冻结模型上下文
配置 TPM 时：估算输入 + 输出预留 <= TPM
```

术语执行采用 v2；正文旧执行器仍保持 v1，迁移属于后续正文任务。tokenizer 不可用时 v2 失败关闭，不退回按字节猜测。RPM 只采用冻结配置明确给出的值，不假设供应商默认限速。超预算先移除更早的只读片段；跨文档或通道合批不共享前文。

## 3. 派发门禁、并发与恢复

新网络请求在写入 paid attempt 前必须同时通过 T08 凭据和完整请求预算检查。直接运行、冲突核对和恢复后的新派发都走同一门禁。缺少或不匹配凭据时拒绝新派发，并保留具体原因，HTTP 为零。

术语批次按冻结并发额度运行，任务完成后立即补位。单项失败不阻塞其他项；截断批次只对未完成成员缩小后重试。暂停或取消后不再填充新任务，但会保存已经返回的付费结果。

请求与进度继续使用现有 JSON 交接：

| 数据 | 路径/记录 | 作用 |
|---|---|---|
| 请求清单与 attempt | `requests/*.json` | 请求身份、成员、预算和状态 |
| 原始模型响应 | 模型响应目录 | 已付费响应的本地回放来源 |
| 提取记录 | `glossary/extraction/*.json` | 每项候选、诊断和终态 |
| 候选池 | glossary 候选记录 | 合并、拒绝和冲突状态 |
| 冻结词表 | freeze/glossary 记录 | 正文阶段使用的不可变术语快照 |

`reserved` 统计已占用的 attempt 额度；`sent`、`unknown`、`succeeded`、`failed` 统计实际越过网络边界的结果。重启不清零这些累计值。若响应已经落盘而状态写入中断，恢复先读取并校验该响应，成功回放不会再发 HTTP。

## 4. T12 证据、冲突与冻结

[candidates.py](../engine/services/terms/candidates.py) 只接受来自当前 primary 源范围的连续引文。错误视图、只来自 context 的引文、虚构引文和缺少源词或别名证据的候选会被拒绝，合法候选仍保留。

构建候选池和冻结前，使用保存的提取项与文档逐条重验候选 ID、内容、证据和状态。冲突核对从这些记录重建标准候选池，固定候选、拒绝记录和冲突组事实，仅允许合法的核对状态变化。

用户词条的模式、作用域、别名和备注不被自动候选覆盖。自动采用项保持 `preferred`。冲突核对只能选择已有候选、缩小到合法作用域或 `defer`，不能创造新译名；它与提取请求共用 T08 门禁和预算检查。

[freeze.py](../engine/services/terms/freeze.py) 只冻结终态提取记录，按实际 primary 源文本统计作用域内词频，并保存 `freeze_id`、输入身份、覆盖、缺口、拒绝和未解决冲突。结束的 unknown，或已经被同身份成功响应覆盖的旧 unknown，不会永久阻塞冻结；真正未结束的请求仍保持暂停。

冻结状态保持区别：`closed`、`closed_with_gaps`、`disabled`、`not_required`。`closed_with_gaps` 允许带明确警告交接，不代表术语完整或正文翻译完成。

## 5. 阶段边界

本阶段没有：

- 把 T08/T11/T12 自动接入生产准备入口；该工作属于 T15。
- 改写正文 translate → proofread → apply_corrections 工作流；该工作属于 T16/T17。
- 生成或发布最终 EPUB；装配、校验和提交属于 T18/T19。
- 修改真实书籍、既有用户断点或调用付费模型。

下一阶段从 T13 开始，为正文批次选择相关术语并构造最小请求投影；它必须消费本阶段冻结的 JSON 结果，而不是重新提取或动态改词表。
