# 多 key workflow 与准备阶段并行计划

## 目标和边界

普通 translate 命令发现 AGNES_API_KEY 及 AGNES_API_KEY_*，按去除首尾空格后的完整值去重，忽略空值和示例值。key 只保存在进程内，不进入书籍 JSON、提示、日志或报告。现有 provider/model、片段身份、词表冻结、回填和出版条件不改变。

这里的 workflow 是一个请求批次的初译、校对及必要修订。同一本书沿用一个状态所有者；正文按 HTML/document_id 独占调度，不同文档可以同时等待接口，同一文档内的批次顺序执行初译、校对和保存。NCX、OPF 等资源同样按 document_id 独占。

## K1：key 发现与模型隔离

集中读取基础 key、dotenv 额外字段及进程环境中的 AGNES_API_KEY_*，环境变量覆盖同名 dotenv 项。稳定排序、去重。基础 key 缺失时可仅使用编号 key。每个 key 构造独立模型及客户端，禁止浅拷贝后沿用其他 key 的客户端。

验证基础 key、仅编号 key、重复/空白/示例值、环境覆盖、独立客户端和异常脱敏。新增源码和文档使用单词名称，每文件不超过 1000 行，不新增依赖。

## K2：workflow 占用与故障切换

增加进程内 key 池，正文中每个 key 同时只分配给一个文档任务。正常情况下该文档所有 chunk 的初译、校对和修订都使用同一 key，文档处理结束或取消时释放。直接调用术语/冲突解析请求也通过同一个机制分配可用 key。

RPM/TPM、限流冷却分别按 key 计算。429 遵循 Retry-After，超时/连接错误及可重试服务错误进入短暂冷却；优先切换其他可用 key，并让后续步骤跟随新 key。所有 key 忙或冷却时等待，不越过限速。取消不能泄漏占用，单个 key 的故障不能让其他 key 的 workflow 停止。

401/402/403 停用当前 key 并尝试其他 key，全部停用时暂停派发。失败计数不能跨 key 累积导致健康 key 被暂停；重试耗尽仍保存失败供下次普通命令恢复。

ModelRuntime.invoke 中现有 attempt 循环是唯一重试计数所有者，不增加池外层重试。每次 attempt 前按 workflow 当前 key 限速；失败先冷却并释放旧槽，再等待其他槽，等待时不持有旧槽或池锁。沿用同一逻辑 request_id，每一次网络尝试仍先保存 attempt，再保存响应和结果。超时先保存 unknown 证据，再建立下一 attempt；新 attempt 的有效持久响应仍可恢复，旧 unknown 和 HTTP 计数不删除。取消同样保存 unknown 并释放占用。切换不能绕过已有重试次数/HTTP 限制；不重新翻译已经保存且有效的初译。真实输入超限仍停止派发。

## K3：调度与断点兼容

默认同时运行去重后 key 数量对应的 workflow；新增或删除 key 后恢复时重新发现，不把 key 列表冻结进书籍配置。现有 --concurrency 默认为 None，可显式限制本次运行的总并行 workflow 数量；无参数使用自动值。该覆盖值只存在本次调用上下文，不写入 PreparationPlan 或新配置字段，也不修改旧配置的请求/预算身份。真实 Agnes 使用当前自动数量或本次显式上限，旧冻结值只为非 Agnes provider 和注入测试 transport 保持既有并发行为。

正文调度在同一文档的全部 run_workflow 外占用 key；术语批次同样使用可用 key 数量扩大并发。独立的冲突解析批次只有在结果可单独保存时才并行，词表冻结仍在全部结果收集后执行。

## P1：独立文档解析与预检

资源解析和原子清单提取使用标准库有界 spawn 进程池，逐文档预检使用有界线程池。主进程读取 ZIP，解析进程只持有独立 bytes 和可序列化输入；不共享解析树或 ZIP 句柄，不写入状态。prepare_book 按既有 paths 顺序收集；预检仍按 document_id 排序并按各自 item 顺序汇总，成员、请求及哈希与串行结果一致。

实测 HCI 同样 8 个最大 XHTML，串行解析 17.512 秒，2 线程 19.981 秒，4 线程 25.512 秒，2 个 spawn 进程 10.188 秒，4 个 spawn 进程 6.605 秒；完整清单哈希相同。因此解析改用进程，保留已有提速的线程预检。默认最多 4 个计算工作者，同时在途输入不超过工作者数；单文档或总资源小于 256KiB 走串行，避免小书的进程启动开销。该阈值只选择本地计算方式，不改变 chunk 或请求预算。

工作进程输入/输出须可 pickle；异常取消尚未开始任务并等待已运行任务退出，不能留后台写入者。输入输出都以完整文档为单位，额外内存受在途文档数限制；此样本单个 pickle 输出最大约 12.6MB，4 个工作者的在途输出约 50.6MB，此外仍有解释器和解析树的内存开销。CLI 的 main 入口保护和 spawn 场景需有回归测试。

## 计划审查

独立审查发现并已补齐四项边界：invoke 唯一拥有重试、unknown 证据与后续成功兼容、本次并发覆盖不改变冻结身份、结果保持既有规范顺序。K1–K3 已按修订实施并通过代码审查。P1 因真实测量改为进程解析，实施前单独复审此调整；准备阶段必须补齐串并行 DocumentPlan、document_hashes 和 PreparationPlan 哈希一致的自动回归。

同时在途的文档数量受工作线程数限制，避免复制整本书或一次提交全部大文档。状态写入、全书汇总、词表冻结、依赖阶段之间和最终打包保持原有顺序。正文合并仍按整个文件/通道执行，不为并行计算引入额外 chunk。

## 实施顺序与验收

1. 审查本计划，先修正 key 占用、故障切换、旧断点和并行写入风险。
2. K1：实现去重和独立模型，运行配置/模型测试。
3. K2：实现占用、独立限速和切换，测试并行重叠、初译校对同 key、重复 key 不增加容量、429/超时切换、取消释放、全部 key 冷却及凭据不落盘。逐条核对 attempt_number、unknown/failed/succeeded 状态和 HTTP 总数；两个 workflow 同时故障的测试必须能证明不互等死锁。
4. K3：接入正文/术语调度和普通 CLI 断点恢复，验证初译复用、自动数量和显式上限。
5. P1：并行资源解析和文档预检，与串行结果逐项比较 inventories、pieces、diagnostics、atoms_hash 和 budget_hash，并用真实 HCI 资源做只读验证和测量。
6. 独立 review 修改后的调用链和边界，修复发现的问题；运行全套测试、Ruff、Pyright、格式和文件行数检查。

完成条件：一次 workflow 在健康期间不跨 key；多个 workflow 实际重叠运行；故障切换的网络尝试可追踪；重复 key 只占一个位置；准备并行不改变原文、映射、顺序和断点。真实书籍验证不重复派发整本翻译，不改写用户当前进度。

## 实施结果与使用

K1–K3、P1 已完成，计划复审与最终代码审查通过。普通 translate 命令不需要新增参数；AGNES_API_KEY 和 AGNES_API_KEY_* 自动参与并去重。需要限制本次总并发时，使用既有 --concurrency，例如 --concurrency 2。不传该参数时自动使用当前全部唯一 key，旧断点的默认 2 不会限制真实 Agnes 调度。非 Agnes provider 和注入 transport 保留原有并发行为。

workflow 正常期间固定当前 key；限流、超时或可重试连接/服务异常在原 attempt 循环内换 key。每个 key 的租约、RPM/TPM、冷却和停用状态在同一运行模型的不同准备/正文 runtime 间共享，客户端与 transport 各自独立。响应和 attempt 仅记录安全编号 key_slot=agnes-N，不保存凭据。未知尝试与后续成功响应均保留，已有有效初译继续复用。

实际状态集成测试覆盖三个 key 同时运行完整初译/校对、超时换 key 后保持 unknown→succeeded 证据、术语批次及冲突批次并发、重启不重复发送以及本次并发上限不改变准备身份。真实 HCI 五分片临时副本恢复全部 15592 个成员，5 个真实配置的 key 均到达派发位置；验证拦截 transport，网络请求为零。用户原翻译进程仍在运行，验证只在临时副本写入，未停止原进程。

真实 HCI 解析测量的 8 个最大 XHTML 合计 3414802 字节、3843 个原子项；串行与线程/进程生成的完整清单哈希相同。4 进程解析 6.605 秒，对比串行 17.512 秒；线程预检 40.986 秒，对比串行 48.059 秒。这是重型资源样本的测量，不代表整本翻译或接口速度。

新的进程解析已增加 atomic 和 legacy 两条路径的 DocumentPlan、document_hashes、完整 PreparationPlan 和 preparation_hash 一致性回归；进程退出和有界提交也有测试。功能在下一次启动命令时加载，已有 Python 进程不会自动更新。未新增依赖、状态文件或用户参数。

## 并发与耗时日志

首次请求成功时显示对应 agnes-N 已验证可用；401/402/403 停用及 429/超时等冷却会显示安全的 key 编号、状态与剩余可尝试数量，不显示凭据。未验证的 key 不直接宣称可用。可尝试数量下降时，调度容量随之下降；全部停用且仍有待办时明确暂停。

每个 workflow 保留一条完成日志，附带使用的 key、已验证 key 数、可尝试 key 数、当前真实 HTTP 并发和累计 HTTP 峰值。HTTP start/end 只更新内存计数，不逐请求打印。耗时分为等待 key、限速等待、接口等待（含超时/重试）和本地/调度剩余时间；总耗时从调度到完成，不能理解为单次 HTTP 时长。

真实 HCI 示例 tx-1e414bcbe03b351f013fc2abe823b76a 的总耗时为 1040.2 秒：成功初译约 46.5 秒、成功校对约 43.8 秒，另有约 120.4 秒超时和 64.9 秒认证失败尝试。其余约 765 秒属于排队、本地处理和调度。该轮曾同时派发 5 个请求，但 agnes-2 至 agnes-5 均返回 401 Invalid token，随后只能使用 agnes-1。新增诊断用于明确显示这种退化，计时与健康状态不会改变请求哈希、预算或断点格式。

## 并行后的本地阻塞修复

HCI 三个有效 key 并行时，每批仍出现 58–83 秒本地/调度耗时。真实断点副本 cProfile 发现：一次运行记录写入约 0.666 秒，紧接的 ReadySession.verify 却用 12.441 秒重新枚举约 20318 条逻辑依赖，产生约 7000 万次函数调用。此前 quick fingerprint 观察所有物理分片，运行状态写入会使其失效，即使准备内容完全没变。

compact 模式现直接从已验证逻辑缓存获取准备依赖的 key/stamp 指纹，以及源 EPUB 的实际 stat。运行记录写入不触发准备重扫；源文件变化、准备记录增删改、外部物理更新仍使证明失效。外部加载代次保证即使篡改者保留逻辑 stamp/大小并更新分片摘要，也必须重新做完整校验。同线程批量事务读取 pending view，分片重平衡仍按逻辑记录追踪，不依赖静态数据恰好放在哪个物理文件。

相同真实 HCI 副本复测：写入后 verify 约 0.007 秒，普通运行写入约 0.646 秒；冷启动正文记录加载仍约 106 秒，此次没有声称解决全部启动成本。没有调用接口或修改原书翻译进度。

日志“接口等待”是 await provider 期间的墙钟时间，可能包含其他 workflow 同步工作阻塞事件循环的时间，并且累计初译、校对与重试。wait_for 的 120 秒也不是能抢占同步 Python 的硬时钟；实际超时回调可能延迟。RPM 是每分钟请求次数上限，不是单次生成响应的时间保证。

此轮修复完成后，全套 1163 项测试通过（309.48 秒）；Ruff、格式、Pyright、差异检查与 1000 行约束通过。真实性能测量及测试均未请求供应商接口、未操作正在运行的翻译进程。

## HTML 独占和保存边界修复

已复现旧错误：只从外部刷新 report.json，准备记录完全没变，全局加载代次仍然变化；在完整核验前后刷新运行记录，会触发 ready dependencies changed during workflow verification。现在去掉上述全局代次，准备身份比较选定逻辑记录的 key、stamp 和实际内容；源 EPUB 仍校验实际文件身份。运行记录、响应、报告更新不再使准备证明失效；即使 stamp 不变，准备内容被修改仍被检测。

一个文档任务顺序处理其未完成批次，健康期间持有同一个 key。失败只切换 key，不增加同文档任务；单项失败持久化后继续后面的批次。全部 key 停用、存储错误或真实准备身份变更仍暂停，并立刻打印一次全局停止原因。

所有正文任务通过同一个保存锁提交给 BodyJournal.save_many。持久化成功后才更新内存记录和完成计数；请求尝试和原始响应仍通过同一 BodyJournal 的同步原子写入，事务内不 await，不新增写入线程或存储文件。每个 chunk 完成后保存，不等 HTML 全部完成。

每个 chunk 仍只输出一条 workflow 总结，附带文档路径、key 和本 chunk 的耗时。自动重试轮次仍沿用文档独占边界。只剩一个文档时，仅该文档任务继续运行。

验证要求：同 HTML 不重叠、不同 HTML 实际重叠；超时后健康文档继续推进；正常保存和外部运行记录刷新不误报准备变化；同 stamp 的准备内容篡改仍被拒绝；取消可恢复、已完成结果不重发；保持现有五个断点文件。另以当前 HCI 书籍进行有限批次真实接口验证。

本次改造全量 1172 项测试通过，最后的并发异常处理补充修改另有 66 项跨模块回归通过。独立审查发现的同时失败异常被吞掉问题已修复：先检查所有已完成文档，再取消剩余任务，保留非取消异常。Ruff、Pyright 和格式检查通过。

经用户授权，在 HCI 当前断点上用真实接口验证 chapter1.xhtml、chapter4.xhtml、chapter5.xhtml 的四个正文批次，共 34 个单元。接口并发峰值为 3，同一 HTML 的后续 chunk 在前一个校对和保存完成后开始，健康任务保持同一 key。首轮模型响应导致 8 个单元需要重试，其余 26 个已保存；续跑复用成功结果和有效初译，最终 34 个全部 reviewed，整书已接受计数为 3572/15408。没有生成部分翻译的成品 EPUB，也没有修改原 EPUB。

验证脚本曾将跨重试轮次的新任务领取不同 key 误判为冲突，已改为按文档任务的租约检查，随后真实续跑通过；该临时断言的诊断和脚本均清理。整书仍未完成，这次仅验证有限批次。冷启动和最终报告生成仍需要读取现有大断点，本次不声称已消除所有本地耗时。
