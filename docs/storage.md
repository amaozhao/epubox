# 状态分片与小请求合并实施计划

## 要求

- 原书旁的同名工作目录保留解压内容和最多五个 JSON 文件：origin、mapping、plan、terms、state。
- 每个持久文件实际编码大小严格小于 400000000 字节；空间不足时不得覆盖已保存断点。
- 普通 translate 命令自动迁移旧单文件状态并继续，不增加参数，不改变记录 ID、内容、版本或哈希。
- 源 EPUB、已接受译文、有效初译和校对凭据保持完整；不以原文补齐失败内容。
- 文件名单词命名，源码每文件不超过 1000 行。

## 实施顺序

1. S1：定义分片格式和记录路由。origin 保存 documents 与准备/源身份；mapping 保存 inventories 和 members；plan 保存 batches、checks、prepared 和 plans；terms 保存 glossary；state 保存 results、requests、responses、frames 与报告。容量不足时调整整条记录的分配，保持最多五个文件。
2. S2：实现原子提交、崩溃恢复和旧格式迁移。所有新内容先完整暂存并校验；提交记录放在 state 内，最终替换 state 完成提交。暂存文件只在事务期间存在，恢复后清理。迁移需持有现有同书锁，不与旧运行进程并发写入。
3. S3：沿用既有 state 读写、glob、stat 和 batch 接口，日常修改只写受影响分片。缓存与恢复指纹覆盖所有分片，避免只监测 state 而漏掉原文/计划改动。
4. S4：验证读写、迁移精确一致、失败回滚/恢复、重复键、文件损坏、尺寸限制、跨进程锁及旧/新 CLI 续传。再用真实 HCI 断点副本验证最多五文件、各文件上限以及日常写入量；安全获得同书锁后迁移原断点。
5. M1：在存储修复后分析日志中的 tx-5fac54d3500e93471dea33d22c32f1fb 与 tx-fd81524525489f882a664cf991b7fa6d。核对实际 HTML、成员、正文 token、已完成间隔、重试分区、有效初译与预算原因，不能仅凭显示数字猜测。
6. M2：修复可合并的短正文被分开的根因。按同 HTML 与下一步操作合并待处理内容，保留完整原子元素、独立回填身份、已完成结果和真实输入/输出上限。实际正文下限使用现有环境配置，允许已确认的最大值浮动。已有译文只校对，确实仅剩一个待处理项的文件不得重翻成功内容凑数。
7. M3：按用户补充要求统一全局合并规则，不限于示例。首次规划、首次调度、部分恢复、手动/自动重试和校对共同使用真实正文浮动上限及翻译、校对完整预算。恢复对保存的待执行批次做线性尝试合并，不能因旧批次已存在就放弃合并，也不能重新规划整本书造成启动卡顿。整本真实断点统计每个未合并边界的原因。

## 全局合并边界

- 同文件、同通道、同下一步操作，按源顺序合并；可以跨过已经完成的片段。
- 环境值 2000 为正文目标；当前容许浮动时，3000 为真正正文上限。不能仅超过 2000 就关闭批次。
- 同一个 Unit 的不同轮次不能混入同一 manifest；不同 Unit 的轮次可以不同。
- 成功或终止的历史请求不阻止未完成项再次合并；未知接口结果需保留原请求所有权和回放证据。
- 结构错误、槽位错误、英语残留不再逐项隔离。真正截断的原请求保留缩小重试边界，防止原样再次超限。
- 每次请求按其阶段核对完整预算；初译与校对分别合并，已有译文的校对使用真实目标文本。恢复合并保存正文批次时，额外核对既有校对预留估计。
- 不跨文件、正文/属性/导航等通道或操作混合。p/table/em/i 等完整结构及列表 li 边界仍遵守既有规则，回填映射不改变。

## 验收

- 真实断点迁移前后逻辑记录内容和 stamp 完全一致，无源文件修改。
- 修改一条运行记录不会重写原文、映射、计划或词表文件。
- 模拟任意提交中断后仍能恢复同一完整事务，不派发未经验证的请求。
- 小请求测试覆盖首次执行、部分恢复、已完成间隔、重试分区和校对修复；实际 HCI 数据证明可合并项在同一请求且逐项正确回填。
- 每阶段完成针对性测试；最终完成集成验证、格式、静态检查与真实命令恢复到首个接口派发位置。

## 实施结果

- S1–S4 已完成。HCI 原断点 37611 条记录迁移前后的内容、stamp、source/run 身份和逻辑哈希一致，源 EPUB 未改变。迁移完成时，原目录包含 origin 200277698、mapping 373550157、plan 174535969、terms 40540938、state 31857049 字节五个 JSON，均小于 400000000 字节；后续运行继续更新对应分片。
- 新建、旧版迁移、单分片写入、跨分片原子提交、崩溃重放、损坏/符号链接拒绝、尺寸上限和整体记录重分配已覆盖测试。更新一条报告仅改变 state，四个静态分片 inode/mtime 保持不变；真实副本更新耗时约 2.3 秒。
- M1–M2 已完成。根因是结构错误重试被逐项隔离，不是这两项的上下文过长。删除这类强制单项分区，保留真实响应截断的按原请求缩小策略。实际 146/21-token 项与另一个同类项组成一批，正文 252 tokens、输入 1555 tokens、上下文为空、预算通过；已有有效译文的项仍只进入校对组。
- 真实五分片副本经过普通命令入口恢复全部 15592 个片段，完成重试重组并到达首个 transport。验证拦截网络调用，未增加原书接口请求；并未以原文替代失败译文。
- M3 已完成全局规则修复：去掉正文目标值的提前关闭，已保存待处理正文按实际浮动上限尝试合并；每个合并候选直接核对整批初译与估算校对预算，不再反复测算所有增长前缀。旧请求是否可复用按其成员的实际未知结果判断，不因存在终态历史请求而排除整条通道。词表只在同一个不可变快照首次使用时计算一次哈希。
- 首次初译与校对是独立请求阶段，初译按初译完整预算合并，校对按实际译文重新合并和核对；恢复时合并旧正文批次额外校验估算校对预算。两种路径都不派发超过其实际阶段上限的请求，不改写已有译文或请求凭据。
- HCI 全书只读验证：71 个未开始正文 HTML 的 933 批、11880 项合并为 904 批，项目和 1536893 正文 tokens 不变。完整调度两次结果一致，为 1047 批、13983 项，耗时约 27 秒。833 个保存正文边界中，596 个受 3000 正文上限限制、152 个受初译输出限制、85 个受估算校对输出限制，未发现可继续合并的相邻边界。
- 18 个剩余小正文批次的原因分别是 13 个同文件只剩一个可处理批次、4 个初译输出限制、1 个待校对阶段与截断分区隔离。元数据和属性短批次均是其同文件、同阶段只有这一批；没有用重翻成功内容或跨文件合并来凑数。
- 最终全套测试 1067 项通过；Ruff、Pyright 和差异空白检查通过。真实书籍验证覆盖迁移、恢复、全量请求合并与派发前预算，不包含新的接口调用或整本翻译完成验证。

## 容量边界

稳态仅有上述五个 JSON；提交期间有自动清理的暂存文件。单条记录或全部数据无法装入五个小于 400MB 的文件时，在修改稳定文件前停止，保留原断点，不删除译文或凭据、不静默超限。
