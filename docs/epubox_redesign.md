# epubox MVP 翻译引擎重构方案

**版本：2.3｜局部失败继续执行与 HTML→JSON 持久化专项修订版**  
**日期：2026-09-28**  
**输入：英文 EPUB；输出：简体中文 EPUB；运行方式：沿用现有本地程序。**

> 本文是本次重构的唯一实施基准，完整替代 v2.2 及更早版本的实施规定，而不是在旧文档后追加补丁。旧版 68 项讨论作为历史分析保留，不再要求开发前逐条证明全部候选风险。本文没有审计实际源码，也没有宣称项目测试、真实模型或阅读器验收已经通过。
>
> **MVP 主线：读书 → HTML/XHTML 解析并保存结构化 JSON → 从 JSON 调度翻译与校对 → 局部失败留档、后续继续 → 逐项落盘与恢复 → 从源模板和有效译文重建 → 验证并生成中文 EPUB。**
>
> **两项强制要求：局部翻译失败不得终止后续独立任务；章节 HTML 的原文、解析计划、结构定位和格式引用必须完整落入 JSON。JSON 不是可选日志，也不能只保存译文。**

## 0. 产品目标、保证边界与不做的事

### 0.1 MVP 完成目标

在支持范围内，用户提交一本英文 EPUB 和现有模型配置后，程序应能完成正文及必要辅助文案的简体中文翻译，保留文档结构、代码、图片和引用，支持中断续跑，并生成中文 EPUB 和可定位问题的报告。

**只保留一种正式完成标准。** 所有应译单元通过本地检查和指定版本的机器校对，相关衔接检查完成，结构与 EPUB 检查通过，才返回 `completed`。MVP 不新增快速模式、跳过校对模式、部分英文混排草稿导出或多档质量配置。失败或未完成结果保存在工作目录；**本轮调度必须继续处理后续所有可执行的独立任务**，不能等失败项修好才翻下一段或下一章。只有最终发布受整书完成门槛限制，不是每个翻译任务都受该门槛限制。

“格式完整”允许中文段内改序，但不允许章节、段落、列表、表格行列被模型重组；不允许链接、图片或代码丢失。“机器校对通过”不等于零错译，更不等于人工精校。最终规范检查也不证明语义和所有阅读器显示效果。[^R4]

### 0.2 必须保留的能力

- 完整语义单元翻译、必要源上下文、用户术语表、源译对照校对与有限修订。
- 段内允许的格式对象改序、合法嵌套、代码/公式/图片保护、白名单属性翻译。
- 超长单元切分与重组、整书内容归属检查、导航与语言更新。
- 有界并发、失败隔离后继续、有界重试、章节解析 JSON 和单元结果 JSON、断点恢复、失败定位及可靠输出。

### 0.3 不纳入 MVP 的建设任务

不建设编码探测或转码体系，保持现有 UTF-8 约定；不做 OCR、图片重绘、DRM 解密、固定版式重排、原音频重新配音或同步、动态脚本翻译、任意格式范围拆合。

不建设 Web 后台、数据库迁移、分布式队列、通用翻译平台、向量库、全书逐词对齐、滚动摘要传播、自动术语发现平台、智能多模型路由、CSS 级联/布局引擎、自动样式物化或字体剪枝系统。

**不因为减少功能而删除正确性检查。** 限定输入支持范围、简化状态与修订策略，而不是关闭校对或让异常内容静默保留英文。

### 0.4 关于现有 epubox

原模块路径来自用户提供的清单。实施时读取真实入口、配置、依赖、相关函数和已有测试，保留已有效的能力；不预设 Python/SDK 版本，不无故更换框架，也不将“存在风险描述”等同于“源码已确认有 bug”。无需先完成一份 68 项全面审计才能开始 MVP 闭环。

## 1. 明确支持范围与提取范围

### 1.1 输入支持边界

正常目标是当前项目可解析的 EPUB 2/3、可重排、静态英文书。代码、数学公式、图表、复杂列表和脚注是正常内容，不能仅因包含这些内容就排除整本技术书。保留源 EPUB 版本，不顺带升级格式。

付费模型调用前检查：源包可读取、路径安全、所需资源可找到、XML 可按项目适配器解析、模型/检查工具可用、输出路径可写，以及支持范围是否满足。

下列情况给出准确原因并停止正式翻译，不实现额外修复系统：正文加密、需脚本生成的阅读内容、固定版式或多版本混合阅读包尚无适配、被译正文绑定未支持的音频同步、源文件含不能处理的签名关系。**字体混淆不等同于正文 DRM**：已支持的字体混淆资源和标识符按原样保留，不做解密/重命名。普通图片、独立音视频不因此被拒绝；仅保留其资源，不宣称其中英语已翻译。EPUB 的阅读顺序、字体混淆、签名与媒体同步各有独立约束。[^R1]

XML 解析沿用已支持当前 EPUB 的适配器，禁止随正文内容联网取外部实体或读取任意本机文件；已有 EPUB 2 所需的可信本地解析支持不因重构被误删。本地引用与外部链接分开处理，不把外链原样保留解释成已验证其在线可达性。

MVP 不自动修复源书。源规范检查中的 ERROR/FATAL 在调用模型前报出并阻断；WARNING 记录但不自动升级为失败。没有安装规范检查工具时在预检失败，不先花翻译费用再生成不合格的“候选完成品”。

### 1.2 内容处理决策

| 内容 | MVP 决策 |
|---|---|
| 正文、标题、引文、列表、表格自然语言、图注、脚注/尾注、旁注 | 翻译；保留源结构归属 |
| XHTML 导航、NCX 标签、章节 `head/title` | 纳入同一任务账本，按 §11 处理复用 |
| 已存在的 `alt`、`title`、`aria-label`、`aria-description` 自然语言 | 白名单属性单元；空值保持空，不补写图像描述 |
| `id/href/src/class/style`、ID 引用型 ARIA 属性、状态值、命名空间及资源路径 | 本地保留，不交给模型改写 |
| 代码块、命令、代码输出、短内联代码 | 原内容保留；短且必要的代码作为只读提示可见 |
| 图片、公式、SVG/MathML 绘图内部及其嵌套说明 | MVP 作为整体资源/子树保留；图外说明照常翻译，不声称图内英语已处理 |
| 已有中文或明确不译内容 | 保留；含英语的混合段仍按完整语境处理其应译部分 |
| OPF 主书名、文字型简介 | 默认翻译；多语言备用标题原样保留；归属不明确则保留该元数据并报告 |
| 作者、ISBN、出版商、原出版日期、标识符 | 不改写；必要目标语言/修改时间另按 §11 处理 |
| `script/style` 源码、注释、纯结构空白 | 不作为自然语言任务，保留并记录类别 |

主输入是英文书，不新增通用多语种识别和繁简转换功能。新生成目标要求简体；已有中文按源保留。不能以“段落含汉字”直接跳过其中的英文。

### 1.3 范围判断优先规则

硬保护的代码/公式内部不是翻译区域。其余区域按明确内容规则、HTML 的有效 `translate` 状态和白名单处理；继承 `translate=no` 时，不翻译该处文字与可译属性，后代显式 `translate=yes` 的处理按适配器规则恢复，但不能越过代码/公式硬保护。用户例外规则在准备阶段显式编译，不能在某次重试中临时改变。[^R5]

正文 `translate=no`、图内文字保留、代码保留是事先声明的合法范围，不是“模型失败后跳过”。需要翻译却失败的单元不能自动改成保留类。

manifest 与 spine 分开使用：盘点所有相关 XHTML 资源，spine 仅决定主阅读顺序；尾注、`linear=no`、导航等独立资源照常纳入。相同资源只提取一次。未声明但被引用的阅读资源进入预检，不在完成率分母中悄悄消失。

## 2. 单机流水线与数据归属

```text
源 EPUB + 冻结的翻译配置
  → Prepare：源快照、资源盘点、预检
  → Extract & persist：解析各 HTML/XHTML，原文+槽位+Unit+格式引用写入 documents/<document_id>.json
  → Commit preparation：初始 UnitRecord 落盘，最后提交 ready 的 bookplan.json
  → Plan from JSON：读取已提交 JSON，上下文、术语、切片计划、请求预算
  → Translate：受限协议、有界并发；局部失败记录后继续其他 item/Unit/章节
  → Validate：响应协议、格式和内容异常
  → Review：源译校对、必要的完整目标修订
  → Coherence：条件齐备的章节执行衔接检查；未齐备章节挂起检查但不阻塞其他工作
  → Assemble：从源模板和已接受结果生成章节
  → Finalize：导航、语言、必要元数据与既有排版策略
  → Validate package：临时打包、重开、结构/资源/规范检查
  → Publish：提交本次真实产物；否则保留可恢复进度
```

### 2.1 数据对象

| 对象 | 责任和关键字段 | 是否可变 |
|---|---|---|
| `BookPlan` | 源哈希、源包版本、资源/阅读顺序、范围规则、冻结翻译配置 | 准备完成后不可变 |
| `DocumentPlan` | 一份 XHTML/NCX/OPF 资源的源结构、源槽位、Unit、引用表、边界关系 | 提取完成后不可变 |
| `Unit` | 稳定 `unit_id`、类型、源槽位区间、投影、源语境、相关术语、注册表引用 | 源表示不可变 |
| `CutPlan` | 属于一个 Unit 的 `plan_epoch`、连续源区间、Segment、虚拟边界与哈希 | 新版本替换，不原地编辑旧版本 |
| `RequestManifest` | request_id、目标 IDs、Unit/plan/revision、wire_hash，以及实际 HTTP attempts/额度 | 请求身份派发后不可变；attempt 状态原子追加 |
| `UnitRecord` | 当前 CutPlan、候选、已接受译文、revision、校对、问题、尝试计数 | 单写入器原子提交 |
| `DocumentStatus` | 本章候选版本向量、衔接检查记录、局部未决问题 | 可派生/可重算，不替代 UnitRecord |

这些是本地对象，不是七个服务。属性、导航、元数据用相同 Unit/Result 契约，只有提取与装配适配器不同。

**持久化是契约的一部分：** BookPlan 对应 `bookplan.json`；DocumentPlan 对应 `documents/<document_id>.json`；Unit 源定义内嵌于 DocumentPlan；UnitRecord 对应 `units/<unit_id>.json`；DocumentStatus/衔接结果对应 `checks/<document_id>.json`。不得只在内存保存 DOM、Unit 或注册表，到整书完成后才补写 JSON。具体字段和保存时点见 §10。

### 2.2 Unit、Segment、Batch 不是同一概念

Unit 决定语义归属和回填；Segment 只解决一个 Unit 确实过长的问题；Batch 只用于传输组批。更改并发和组批不改变 Unit，也不删除仍有效的译文。切点变化可能影响译文，所以只使**该 Unit 的全部 Segment 和相关校对**失效，不试图自动拼用新旧切片。

批次内容变化可能影响模型实际输出，不承诺两次生成完全相同。缓存接受规则基于固定源文、声明的语境、术语和协议；另外保存实际请求哈希用于复现。模型不得依赖同批其他待译项补充上下文；需要的信息必须放进显式只读语境。

### 2.3 冻结输入与允许的局部变化

同一运行中，源书、目标语言、保护策略、提示、模型生成配置和用户词表固定。用户更换这些配置时新建运行；MVP 不实现任意配置变化的精细增量缓存或自动词表依赖传播。

运行内允许：有界重试、单元修订、该 Unit 的 CutPlan 升级、重新执行过期的章节衔接检查。更改 CutPlan 时，**不可变 BookPlan/DocumentPlan 不变**；新切片与状态一起写入 UnitRecord，从而解决“源计划不可变却要原地重规划”的冲突。


### 2.4 哈希与版本的唯一含义

`source_hash` 是源 EPUB 字节哈希；`logical_hash` 覆盖 Unit 源内容、保护/移动规则、目标语言、固定源语境、适用术语、提取/协议/提示版本和模型生成配置；`plan_hash` 覆盖当前 CutPlan（未切片时也有单片计划）；`input_hash = hash(logical_hash, plan_hash)`。

`target_hash` 取当前完整目标事件流/切片集合的确定性序列化；`revision` 是该 Unit 当前目标生成代次的单调版本号，不随重规划归零；该代次可先只有部分 Segment 结果，完整候选要等全部必要片段到齐。校对记录绑定 input_hash、revision、target_hash、校对配置和该次实际语境哈希。实际请求另存 `wire_hash`，包含完整消息而不保存密钥。

所有哈希输入使用同一版确定性序列化规则，不能直接 hash Python 对象的内存表示。Batch 组成、完成顺序、并发数不参与 Unit 身份；输出排版变更单独保存 output_policy_hash。约束或源义发生变化时不冒充“只改排版”。

**补充 `record_version`，不与 `revision` 混用。** 每次原子保存 UnitRecord（包括错误、用量、某一个 Segment 的进度）增加 record_version；只有主动开始新的目标代次/修订/重规划才推进 revision。相同 plan_epoch/revision 下，互不重叠 Segment 的并发结果可以合并进最新记录，不能因为另一个 Segment 先落盘就被判为整 Unit 过期。协调写入器检查请求身份、对应 item 的输入/目标版本，再以最新 record_version 提交。

初始目标代次在派发前分配并落盘；未形成完整目标时 `target_hash=null`，不能校对或接受完整 Unit。初译重试可填补当前代次尚缺的片段，不另建一个代次而使其他片段作废。修订一个已有目标则创建新代次，未修改的片段只能在本地显式继承后使用。旧代次迟到响应仍拒绝。

## 3. 提取：语言连续，但源归属可核查

### 3.1 独立源槽位账本

遍历原树的元素 `.text`、子元素 `.tail` 和白名单属性，记录 `node_key + slot_kind + 原字符串 + 处理类别`。一个槽位可以被切成连续源区间，但所有区间必须覆盖原字符串，且没有重复归属。空白不一定入模，却必须有去向。`.tail` 是元素后、父级混合内容中的文字，不能随保护子树无条件复制两次。[^R2]

每个区间只属于：一个应译 Unit、保护内容、结构空白或事先声明的范围外内容。另用独立枚举核对提取覆盖；不能用 chunker 自己输出的数量证明 chunker 没有漏文本。

**结构所有权与属性所有权分开。** 图片子树归保护对象，但其允许翻译的 alt 槽位可归属性 Unit；这不构成重复占有同一正文。代码/公式内部则按 §1 的硬保护范围处理。

### 3.2 语义 Unit 划分

普通段落、标题、引文为完整 Unit；`em/strong/a/span` 不自动切断一句话。多段列表项与嵌套列表递归提取，容器不再次拥有子段文字。`body` 裸文本和相邻内联元素形成虚拟文本区域，遇到块级内容结束；不会为方便回填向原书新增 `<p>`。

表格按单元格或其段落提取，保留 `rowspan/colspan/headers` 等结构。明确的表头关联直接使用；不明确时提供有限相邻行列文字及坐标，不猜测“第一行一定是表头”。图注单独提取，不把整张 figure 的媒体属性送入模型。

对代码空白、`xml:space`、预格式区域不做全局 strip、排版缩进或空白合并。代码中的英文注释不顺带翻译。纯代码/纯结构区域不创建空的模型任务。

### 3.3 保护对象与只读提示

大代码块、图形内部、复杂公式保留在本地。短内联代码也由本地恢复，但可在 `hints` 中提供原始短文字；例如 `finally` 或 `memory_order_relaxed`。这比把所有关键术语隐藏成无信息编号更利于理解。

有确切依赖的代码解释可携带预算内的源签名或原代码片段，不能自动生成未经核实的代码摘要。初译、修复、校对都使用同一投影和注册表，不能在校对阶段重新塞入全章 HTML。

## 4. 受限格式协议与中文改序

### 4.1 三种本地引用

| 形式 | 含义 | 装配行为 |
|---|---|---|
| `⟦+g1⟧…⟦-g1⟧` | 可译文字的原始内联范围，如强调/链接 | 用本地原标签/属性创建一次范围 |
| `⟦=x1⟧` | 不可改写的原子对象，如代码、公式、图片、脚注引用 | 恢复一次原子对象；根 tail 不随对象复制 |
| `⟦+b1⟧…⟦-b1⟧` | 本地虚拟约束区间，仅在硬边界附近使用 | 验证边界后消去，不生成新 HTML 元素 |

普通无格式段落只传文本，不添加逐词 ID。属性/纯文本元数据 Unit 只返回文字，不接受控制标记；字面定界符仍遵守转义规则。白名单属性只适用于 §1 明确允许的区域，不能借此把硬保护公式内部改写。

`g` 保存原节点身份、原父范围、是否允许同父改序及源覆盖文字；`x` 保存原子子树、原父范围、边界类型和只读提示；`b` 保存原区间、父范围及固定顺序。原始 href、class、style、命名空间和长属性不进入输出协议。

### 4.2 可实际执行的移动规则

普通 g 与非硬边界 x 可以在获得许可的**同一父范围、同一 b 区间**内整体移动；内部父子关系不变。不同 g 不因标签名相同就互换身份。禁止删除、复制、改父节点、跨 Unit、拆成不连续范围或把两个原范围合并。

脚注引用作为 x 保留 href/注号；同一父范围内多个注号的相对顺序默认固定。其周围文字可以自然调整，但**仅保留位置/次数不能证明脚注仍指向同一论断**。源引用附近原文、目标附近译文及必要脚注正文进入绑定审查，不把程序推测宣称成确定语义。

`br`、页码标记或明确的结构空锚点需要硬边界时，在其原父内容流中建立 b 区间，固定 `b1 → x1 → b2`；包含硬边界的祖先范围向 Unit 根逐层锁定相关兄弟顺序。虚拟区间在原树嵌套内生成，不能跨越原 g 造成交叉。仍发送完整 Unit 的投影以便理解，不对每个 `.text/.tail` 单独调用模型。

若某一源布局无法生成合法、无重叠的约束区间，准备阶段报告该 Unit，保留其他 Unit 的可处理状态；不通过静默删除锚点解决。普通 wbr 不等同于页码：保留对象，在原父范围内按中文断行意义审查，不承诺它对应原英文字符偏移。

### 4.3 改序示例：身份跟着含义走

```html
<p>Compared with <a href="#ssd">an SSD</a>, <a href="#hdd">an HDD</a> is slower.</p>
```

本地定义 `g1 → #ssd`、`g2 → #hdd`。一条合法目标投影是：

```text
⟦+g2⟧机械硬盘⟦-g2⟧比⟦+g1⟧固态硬盘⟦-g1⟧慢。
```

由本地生成对应链接，不按“第一个链接”或源字符偏移猜位置。把 g1 包在“机械硬盘”外面仍可能结构合法，因此 §8 必须检查实际源范围—目标范围含义。这里借鉴 XLIFF 的身份和许可分离，不实现整套 XLIFF。[^R6]

### 4.4 转义、解析与请求身份

投影层先转义反斜杠和字面定界符：反斜杠为 `\\`，字面 `⟦/⟧` 为 `\⟦/\⟧`；之后再交给 JSON 序列化。接收端先解 JSON，再按字符扫描投影转义与合法标记。未知控制 ID、未闭合范围、交叉、重复、悬空转义都拒绝。

普通 `<p>` 字样是文字，写回时作为 XML 文本转义，不能被当成模型新建的 HTML。不能对字符串全局 replace 来恢复对象，也不能先“修复成合法 HTML”再通过。

`input_hash` 不要求模型计算或回传。派发时本地记录 `request_id → 待译 item_id、unit_id、plan_epoch、input_hash、base_revision、注册表`。响应的 request_id/item_id 与这一记录严格匹配；模型不能声明其他 Unit 的完成状态。相同局部 g1 名称只在当前 item 注册表有效，不跨单元查找。

### 4.5 JSON 示例：字段就是实现约定

下面是未切片 Unit 的请求数据部分；系统规则和只读上下文可由现有 SDK 分层承载。

```json
{
  "protocol": "epubox-text-1",
  "request_id": "r001",
  "target_language": "zh-Hans",
  "items": [
    {
      "item_id": "u007",
      "source": "Use ⟦=x1⟧ to release the ⟦+g1⟧resource⟦-g1⟧.",
      "context": {"section": "Exception handling", "previous": "", "next": ""},
      "terms": [],
      "hints": {"x1": "inline code: finally; restore once", "g1": "emphasis: resource"},
      "constraints": {"reorder": "same_parent", "fixed_groups": []}
    }
  ]
}
```

```json
{
  "protocol": "epubox-text-1",
  "request_id": "r001",
  "items": [
    {"item_id": "u007", "target": "使用 ⟦=x1⟧ 释放⟦+g1⟧资源⟦-g1⟧。"}
  ]
}
```

切片时 item_id 由本地生成并关联 `unit_id/plan_epoch/segment_id`，不依赖模型拆字符串推断。条件较复杂时 constraints 还包含 b 区间和各引用的父范围；不把原 DOM 传给模型。

响应整体必须完整解析，拒绝重复 JSON 键、非法数值和异常深度/大小；Python 默认解析对重复键较宽松，需要显式收紧。[^R7] 顶层 protocol/request_id/字段结构不合法时整批无效；合法顶层中的单个 item 字段或标记错误只拒绝该项，未知 item_id 不写入任何 Unit。缺项只影响缺失项；同 ID 重复的全部候选无效；其他独立项通过验证后可保存。**JSON 截断或整体无效时，不从半截数组抢救子对象。**

字段类型合法仍不足以写入 XHTML：目标中 XML 不允许的字符、孤立代理字符和无效编码序列必须拒绝，不静默删字修复。对白名单属性使用同一检查，文本经 XML API 正确转义。

## 5. MVP 样式策略：保留保护，但不做 CSS 引擎

### 5.1 纠正原例子的解释

`p > a:first-child` 匹配的是“作为 p 第一个元素子节点的 a”，不是任意情况下的“p 中第一个链接”。若前面已有 em，它可能一个链接也不匹配。位置伪类和兄弟组合器确实会使元素改序改变匹配对象。[^R3]

### 5.2 有限保守扫描

复用可用 CSS 解析器读取内联样式、style 元素和本地样式表；本地 import 按有限递归读取。MVP 不计算级联、媒体实际生效条件、布局或所有候选排列。扫描结果只有 `reorder_allowed / locked / unknown`。

允许改序的最低要求：依赖读取完整，选择器只使用已支持且不依赖兄弟顺序的类型/class/id/通配/子代/后代组合；条件规则按所有分支可能生效保守收集。涉及位置/兄弟、伪元素、生成内容、计数器、未知选择器或无法解析规则时，不凭正则推定安全。

已知敏感规则能可靠定位时锁定相关父范围；无法定位时锁定该文档的内联对象顺序，而不是删除样式或拒绝整书。明确方向性、ruby、块级显示等结构不当作普通可移动强调范围。MVP 不承诺这类复杂语义结构自动改写；其中已声明外语保留，其他应译文字无法可靠处理时给出局部待处理项。

锁序只限制元素顺序，仍让模型理解完整段落并调整允许的文字表达。若确实无法兼顾自然中文与约束，进入有限修订，然后明确留下最小待处理 Unit；不得把“安全锁死后翻不出来”当作成功。

### 5.3 不夸大样式保证

这项扫描只用于**改序许可**，不能证明所有 CSS 渲染含义不变。目标语言、文字长度、字体回退本来会改变显示。原 CSS 原样保留；不把位置选择器展开成新内联样式，也不新增自动字体优化。

若目标语言或可译属性变化影响 `:lang` 或属性选择器，作为显式目标变化和样本阅读检查处理，不能声称锁住元素顺序就解决了所有样式问题。

测试中的“增加无关长属性不影响翻译”必须真正无关：例如没有样式或规则引用的 `data-trace`。不能任意改变 class/style/translate/href 后仍要求投影和移动策略完全相同。

## 6. 预算、长单元与切片恢复

### 6.1 预算以真实请求为准

`最终输入 I + 输出预留 O + 安全余量 M ≤ 上下文容量 C`，并满足服务商单独输入/输出约束。输入包括系统规则、schema、上下文、术语、投影和 hints；校对输入还包括目标译文。先确保**翻译和校对两个阶段都能装下**，再派发。

有实际 tokenizer 就使用；没有则保守估算并记录误差，不伪造精确 token。输出按中文及 JSON/标记开销预留，不只按英文字符数估算。代码块已经本地保护，不因长属性导致拆分自然语言。

### 6.2 拆分顺序

先缩小 Batch，单个 Unit 仍超限才按源句界/从句边界切分。所有源区间连续覆盖，保护原子和 Unicode 字符簇不能从中截断；缩写、版本号、小数使用项目反例校验，句号不是唯一断句依据。[^R8]

短段、列表短项和短脚注不为了均匀长度拆分。只读邻接源文明确不属于待译内容，不能重复写入目标。所有切片最终仍回到原 Unit，不新增段落或表格格子。

### 6.3 虚拟边界：源范围只恢复一次

CutPlan 在事件流上切分，记录每个边界的原 g/b 范围栈；不截断投影字符串。跨切片的同一 g 使用本地登记的虚拟起止边界，让各切片可独立验证。

```text
源：       g1 开始 —— 内容 A —— 内容 B —— g1 结束
切片 A：  原始 g1 开始 —— A —— 虚拟 g1 结束
切片 B：  虚拟 g1 开始 —— B —— 原始 g1 结束
最终：    原始 g1 开始 —— 译 A + 译 B —— 原始 g1 结束
```

虚拟边界的位置、顺序和层级由 CutPlan 固定，不能被模型挪到切片中间。合并前核对相邻虚拟栈，移除且只移除登记为虚拟的事件；所有实际源事件和原子对象最终恰好使用一次。**“每个引用一次”针对完整 Unit；切片中的虚拟重复按 CutPlan 核对，不能被普通重复检查误拒绝。**

切片不能改变跨边界范围的外侧父关系或跨 b 硬边界搬运内容。拼接不自动加空格、删重复句或移动标点；接缝是否自然由 §8 审查。

### 6.4 重规划：MVP 只支持整 Unit 升级

预算不足、校对装不下或接缝语义冲突时，允许在额度内生成该 Unit 的新 CutPlan：可把需要联合翻译的相邻源区间重新规划，使用更合理的切点。`plan_epoch` 增加，并原子替换 UnitRecord 中的计划和待处理状态。

**该 Unit 旧切片全部不再作为有效结果使用；其他 Unit 保留。** 旧候选可留作诊断；不实现部分新旧切片嫁接。默认最多一次自动重规划，预算不足或仍冲突则待处理，不靠无限拆小保证完成。重规划不清空尝试次数。

不根据英文源偏移切中文。已切片目标按原 segment 身份保存。未切片目标若校对时超限，优先减少批次和非必要上下文/说明；仍不够则按上述流程从源重新规划，不能截取中文字符硬凑校对请求。

## 7. 语境和术语：保留实际价值，删除平台化设计

每个 Unit 携带固定的书名、章节/小节标题、预算内的前后原文、必要表头或脚注说明和相关词条。先保留影响含义的上下文，再考虑均匀组批；不携带完整 HTML，不默认使用上一个模型生成的摘要。

MVP 复用用户词表导入，词条包含 `source、target、scope、mode、note`。mode 为 `preferred / required / keep_source`；required 只用于已明确义项和范围的词条，不能将 `memory` 在全书强改为“内存”。允许空词表；用户指定文件加载失败要报错，不能假装是空词表。

不新增强制 NLTK 下载、自动发现全书术语、逐词对齐或在线词义分类平台。若旧项目已有效提供候选提取，可作为准备阶段的非必需增强；候选不自动硬锁，失败不影响合法的无词表翻译。确定的词表在运行前冻结。

词条检查以源适用范围和目标具体范围为依据；全段目标词次数一致不是充分证明。普通数字/单位差异先区分等价格式和数值变化；版本、API、引用编号等明确常量按保护规则检查。英文残留、重复和简体要求是辅助信号，不用简单英文比例或汉字比例决定整书质量。

## 8. 校对与衔接：有限、可恢复、不会误晋级

### 8.1 Unit 状态与接受条件

```text
pending → translating → candidate → local_valid → reviewing
  → no_change 且校对条件满足 → accepted
  → replace → 新候选 → 本地验证 → 一次完整复核 → accepted / needs_attention
  → needs_attention / 校对失败 → 保留有效候选，不晋级
```

`accepted` 只表示**当前 Unit 的指定译文版本满足单元检查**。章节衔接和最终打包仍可能未完成，因此它不等于全书 `completed`。

每个 UnitRecord 分开保存最新候选、上个有效候选、已接受版本（如有）、本地检查、校对和未解决项。源提取覆盖为 100% 不能证明模型语义无遗漏。

接受条件明确为 `accepted_revision == active_revision`，且输入/目标哈希与本地检查、校对记录一致。新候选选为活跃版本后，旧 accepted 仅作历史保留。若旧译文已有必须修复的问题，修订失败不能通过回滚旧译文来恢复“完成”；该问题保留为局部未决，不中断其他独立任务。无效响应本身不覆盖活跃候选，但其未解决的修复要求仍必须保留。

### 8.2 一次校对覆盖什么

校对是独立于初译的源译对照调用，可以复用同一个模型，但不是让模型沿着自己的初译聊天记录自我肯定。输入包含源投影、候选目标、固定源语境、相关术语，以及**从实际目标事件流提取**的格式覆盖范围。模型不获得文件、代码执行或外部访问工具。

检查五项：`accuracy`（漏义/增义/否定/条件/数值/比较）、`fluency`（自然中文）、`terminology`（适用词条）、`bindings`（链接/强调/注释的含义归属）、`script`（新生成文字的简体要求）。前两项必须实际审查；terminology/bindings 只有本地计划判定确实不适用时才允许 `not_applicable`。不以模型自报置信度放行。

链接源范围 `an SSD` 却覆盖目标“机械硬盘”，或脚注移动到另一论断后，可以结构合法，却应在这一步被识别为绑定问题。结构检查不能替代语义审查，语义审查也不能替代结构检查。

### 8.3 校对响应与修订规则

```json
{
  "protocol": "epubox-review-1",
  "request_id": "r002",
  "items": [
    {
      "item_id": "u007",
      "base_revision": 1,
      "decision": "no_change",
      "checks": {
        "accuracy": "pass",
        "fluency": "pass",
        "terminology": "not_applicable",
        "bindings": "pass",
        "script": "pass"
      },
      "issues": []
    }
  ]
}
```

| decision | target 字段 | 处理规则 |
|---|---|---|
| `no_change` | 禁止 | checks 必须满足本地适用性；不得包含未解决的 major/critical 或 uncertain |
| `replace` | 必须是该 item 完整目标 | checks/issues 描述被审查的旧版本；新 target 先成为候选，不能直接 accepted |
| `needs_attention` | 禁止 | 保存问题；不接受、不隐式恢复原文为完成 |

checks 值限定为 `pass/fail/uncertain/not_applicable`。issue 至少有 `code、severity、message`；severity 为 `minor/major/critical`。minor 可以带明确警告继续；未解决 major/critical、必需检查 fail/uncertain 均阻断。

本地从 RequestManifest 校验 `base_revision + 目标哈希 + plan_epoch`，不让迟到结果覆盖新版本。修订后重新跑**完整的本地检查与五项校对**，不是仅复核原问题，避免改通顺时引入新的否定/数字错误。复核再要求修改或无法判定时进入待处理，不无限“修改—复核”。

对切片，item 对应 segment；响应字段仍叫 `base_revision`，值统一指所属 Unit 的版本，计划版本由本地 RequestManifest 校验。不要为切片再引入语义不同的 base_unit_revision 字段。完整目标修订在同一 UnitRecord 中一次提交；**此前每个 Segment 的成功或失败都已逐项落盘，不等其他 Segment 到齐才保存**。Segment 级审查通过记录可以复用，但只能用于完全相同的目标片段/计划/语境；改动的切片重新审查，所有接缝重新核对。没有任何切片直接写入章节。

### 8.4 章节衔接的有限快照流程

各 Unit 的翻译/校对独立推进，不设“本章全部成功后才开始下一章”的门槛。只有本章**实际参与衔接的全部 Unit 当前版本已 accepted**，才启动本章衔接检查；缺失依赖时记 `blocked_dependency` 及缺失 IDs，不浪费调用、不记为通过，也不阻塞本章剩余任务和后续章节。独立属性、独立元数据不作为叙述衔接的前置依赖。条件齐备后：

1. 冻结该章节的当前 Unit 版本向量和各长 Unit 的目标切片。
2. 按源阅读流生成有限重叠窗口：覆盖长 Unit 的所有切片接缝、同小节连续叙述的相邻 Unit；表格/注释按自己的关系分组，属性和独立元数据不冒充叙述相邻。
3. 窗口同时提供相邻源文和冻结译文，检查指代、称谓、术语与接缝是否自然。窗口只返回问题和所涉 IDs，不返回自由合并的章节译文。
4. 有问题时，在额度内只修订指定 Unit；按 §8.3 重新接受这些 Unit，再冻结新快照。
5. 最多一次自动衔接修订轮次后复查；仍有重大未决项则待处理，不继续传播修订。

长文本窗口可以只截取接缝附近的只读源/目标文本用于上下文；这些截取偏移**不能用于写回**。真正修改仍使用 item 的完整目标或从源升级 CutPlan。

章节检查记录绑定所有参与衔接的 Unit 版本向量；任一参与者后续修改，该章节检查变为过期，需要重做本章固定窗口扫描；独立属性改动不使叙述检查过期。MVP 采用这个粗粒度但明确的规则，不实现动态邻接译文依赖图。其他章节不因本章修订全部重翻。

### 8.5 最小人工修复入口

MVP 不做人工校对 UI，但提供本地修订文件导入能力，避免 `needs_attention` 没有退出路径。修订文件指定 unit_id、base_revision、plan_epoch、完整 target；切片 Unit 提交其完整切片目标集合，不按英文偏移修改中文。

导入产生新候选，重新走同一结构、校对、衔接流程；不能通过编辑 `accepted=true` 绕过验证。过期修订拒绝并给出当前版本。命令名称沿用实际 CLI，新增参数是否为 `--repair-file` 由实现确定，不将示例参数写成当前已存在命令。

## 9. 并发、预算与错误处理

### 9.1 一个调度入口

翻译、校对、修复、衔接检查共用调度器；默认网络并发 2，可按当前服务商额度调整。限制已配置的 RPM/TPM 和在途量，429 后退避；不承诺永不遇到服务商限流。

禁用 SDK 隐式重试或把它纳入同一计数。模型超时可能已在远端执行并收费；没有服务商幂等能力时，不承诺请求严格只执行一次。

### 9.2 重试额度不随版本重置

初始上限是工程默认值，不是性能实测：一个初译处理周期内，每个 item 初译 1 次，协议修复最多 1 次，定向重译最多 1 次；正常校对 1 次，修订后完整复核最多 1 次。唯一一次章节衔接修订可启动一个新的指定 Unit 修订/完整复核周期，但仍受下述累计额度约束；不是每产生一个 revision 都能新开周期。传输重试另设不超过 2 次/逻辑请求，并计入实际 HTTP 请求总数。

同时设置**跨 plan_epoch/revision 的 Unit 累计额度**和运行总额度。重规划、协议错误或衔接修订不能清零这些计数。切片数多的 Unit，额度按初始计划规模分配并写入记录：初始默认 `unit_http_limit = 24 × max(1, 初始 Segment 数)`，一次含该 Unit 的实际 HTTP 请求记一次；同批多个 Unit 的归属计数不用于相加计算全局请求数。新增切片使用剩余额度，**该 Unit 耗尽时只将其待做项挂为 needs_attention，继续其他有额度的 Unit**，不能因细分自动无限扩容。章节衔接只读调用另有默认 `6 × 初始窗口数` 的总 HTTP 上限（含重试）；生成式修订仍消耗 Unit 额度。运行 HTTP 上限默认不超过各 Unit 额度加衔接额度之和，用户还可设置更低的运行限额。这些上限限制浪费，不保证所有错误分支都能在默认额度内完成。

记录实际请求数、已知输入/输出 token、失败/重试/校对开销。无可靠价格配置不输出伪精确费用；只有已知计费数据才显示金额。预算作用域必须区分：Unit 额度触顶只挂起该 Unit；章节衔接额度触顶只挂起该章衔接检查；**运行总额度触顶才停止全局新派发**。已完成结果保存。额度增加必须由用户明确启动续跑参数执行并记录，不自动调整。

### 9.3 错误作用域：继续执行与停止发布分开

| 错误/限制 | 最小影响范围 | 本轮必须采取的动作 |
|---|---|---|
| 单项漏字段、空译、标记错误、退化、模型明确拒绝当前文本 | item；属于其 Unit 的完成状态受影响 | 保存失败，在有限额度内修复；失败项不得阻止后续 item/Unit/章节 |
| 单项源译校对失败、严重错义/绑定问题、修订复核未通过 | 被审查 item/Unit | 保存候选与问题，不 accepted；其他翻译与校对继续 |
| 完整可解析 Batch 中一个 item 失败 | 该 item | 同批其他独立合法结果分别保存；不回滚整批 |
| Batch 的 JSON 整体截断/不可解析 | 本请求涉及的所有 item | 本批不接受子结果，拆成单 item 请求或缩批重试；其他批次继续 |
| 单个请求暂时超时/可重试网络错误 | 本请求 | 退避后有限重试；没有全局故障证据时不终止整书 |
| Unit 自动尝试或累计额度耗尽 | 该 Unit 的剩余工作 | `needs_attention`，继续其他有额度的 Unit；不得清零计数 |
| 单章衔接失败、衔接额度耗尽或等待失败标题派生导航 | 对应检查/派生依赖 | 挂起该步骤，继续独立翻译任务；失败章不会放行正式输出 |
| 可以明确隔离的局部提取/装配不支持 | 已登记源范围或文档 | 保存源位置和阻断问题，其他已验证独立任务继续；归属无法界定时不能伪装可隔离 |
| 429 | 共享服务商调度 | 共享冷却/降速；恢复后继续；超过本轮服务恢复上限则运行 paused，不将大量任务逐项烧完额度 |
| 鉴权/账户余额/共享模型配置错误，或确认持续不可用的公共服务 | 运行 | paused；停止新网络派发，尽力保存已完成结果 |
| 运行总预算耗尽、用户取消 | 运行 | paused；停止新派发，保存进度；不是删除失败项 |
| 源包/规范预检失败、源身份不符、共享源计划损坏、不可隔离程序异常 | 运行 | failed；不继续基于不可信计划翻译 |
| 磁盘满、写锁丢失、持久化失败 | 运行 | failed；停止新派发，不能继续付费生成无法安全保存的结果 |
| 发布校验/提交失败 | 发布步骤 | failed；保存此前有效译文，修复后重做装配/发布，不自动整书重翻 |
| 迟到响应、人工修订版本过期 | 该响应/修订 | 拒绝覆盖；当前有效工作照常继续 |

§1 的全局输入预检仍先于付费调用；“局部失败继续”不表示读取错误、源书无效或共享存储损坏也强行执行。能隔离的错误必须带确定的 source/document/unit/item ID；无法定位其影响的内部异常不得被 `except Exception: continue` 隐藏。

### 9.4 非 fail-fast 调度：后面的内容必须自动继续

**调度单位是可执行 item/步骤，不是“必须全部成功的一章”。** 稳定源 ID 决定归属；网络完成顺序不决定输出顺序。所有准备完成的文档加入同一个有界就绪队列；不必一次把整书 DOM 载入内存。

执行规则如下：

1. 派发前保存 RequestManifest、额度预留及目标 item 的 in-flight 身份；成功落盘后才发送。每次真实 HTTP 调用分配独立 attempt_id，并在运行总数中记一次；同一逻辑请求的传输重试仍分别计数，不按 Batch 中 Unit 数重复累计运行总数。
2. worker 把**已识别的单项内容/协议/请求错误**转换为带 scope 的结果交给协调写入器，而不是向整书调度层抛出普通未分类异常。
3. 每个成功结果或失败记录都立即合并进对应 UnitRecord 并原子写入。失败持久化后释放该任务位置，让后续独立任务得到执行机会。不能等整章/整书完成才保存。
4. 常规未尝试任务与已到期重试公平调度。有限的传输重试可在当前 worker 内进行；内容反复失败必须隔离为单项并让出队列，不能靠无限重试卡住下一段。并发设为 1 时也必须继续后续内容。
5. 一条坏结果不能取消其他正常在途任务；全局停止、用户取消与不可隔离故障除外。显式取消应清理后传播，不能被当成普通翻译失败吞掉。
6. 无可执行任务且无在途/本轮可自动到期重试后，才汇总结束状态：有未决局部问题为 needs_attention；满足所有完成条件才装配发布。不能在发现首个失败时提前 return，也不能永久等待需要人工解除的 blocked_dependency。

如果项目使用 asyncio TaskGroup，要特别处理其“子任务未处理异常会取消同组其他任务”的行为；应在 worker 边界把已知局部失败转成数据，同时保留全局故障/取消的传播。不能仅替换一个并发 API 就声称失败隔离已经实现。[^R10]

**示例（不表示实测）：** 同章 `u001` 成功、`u002` 翻译失败、`u003` 校对失败、`u004` 成功；下一章 `u005` 也应继续并保存成功结果。本轮结束可以是 needs_attention，但 u004/u005 不能停在未尝试。最终发布仍等待 u002/u003 补齐。

### 9.5 长 Unit、依赖与失败恢复

长 Unit 的 `s1/s2/s3` 共用 CutPlan。s2 失败，s1 的合法目标照常保存，s3 必须继续翻译；不因 Unit 尚未 accepted 就不派发其余 Segment。**同一 plan_epoch 不变时，续跑复用 s1/s3，只补 s2**。仍未齐备时不合并完整目标、不接受 Unit、不写入正式 EPUB。

MVP 可以等长 Unit 的全部翻译片段齐备后再进行完整的片段校对与接缝检查，不必新增逐片依赖传播器；但保存已完成片段是强制要求。只有 §6.4 的**主动 CutPlan 升级**才使该 Unit 全部旧片段过期，不能把普通失败续跑误做整 Unit 重规划。

后续正文使用已保存的源语境和冻结词表，不依赖失败段落的中文译文。衔接检查、标题派生导航等确有依赖的步骤写 `blocked_dependency`，保存所需 IDs/版本；依赖补齐后重新入队。等待依赖不消耗模型请求和重试额度，也不减少必需内容数量。

第一次取消停止派发并尽力保存已返回结果；强制取消可立即终止。恢复从持久 JSON 记录重建状态，不把曾经 in-flight 的请求当成完成。

## 10. HTML→JSON、结果 JSON 与断点恢复

### 10.1 必须采用的文件结构

```text
work/<source_hash>/<run_id>/
  source.epub                   # 已校验的只读源快照
  bookplan.json                 # 全书索引、冻结配置、document JSON 哈希、必需任务清单
  documents/
    <document_id>.json           # 每份 HTML/XHTML 的原文+解析计划，不可变
  units/
    <unit_id>.json               # 可变：CutPlan、各 Segment、候选/校对、错误与累计计数
  checks/
    <document_id>.json           # 衔接版本向量、等待依赖和检查结果
  requests/
    <request_id>.json            # 本地请求身份、派发预留、已知响应/用量；无密钥
  staging/                      # 临时待验证产物
  publish.json                  # 本次提交意图/完成凭证
  report.json                   # 可重算的全书进度、失败和依赖摘要
```

**每个 EPUB 内的 HTML/XHTML 资源保存一份明确的 `.json`，不是只写一个 documents 目录，也不是到翻译结束才导出 JSON。** NCX/OPF 的解析计划使用相同 DocumentPlan 外壳，由相应适配器处理。不是把每个 ZIP 资源都当 HTML；图片、字体和其他二进制保留于源快照，不转 base64 塞入章节 JSON。

unit/document ID 由源哈希、资源路径、源位置和提取器版本生成，不取自译后标题。文件名只使用本地产生的安全 ID。源快照建立后复核哈希；输入复制时变动则重新准备，不用书名复用旧解压目录。

### 10.2 章节 JSON 保存什么：原 HTML 与已解析计划共同持久化

MVP 采用**原始标记字符串 + 可序列化的解析计划**，不另造完整 DOM 数据库或通用 XML AST 标准。字段必须能从普通 JSON 加载；禁止 pickle、进程地址或只在内存有效的 lxml Element 引用。

| DocumentPlan 字段 | 必须保存的内容/约束 |
|---|---|
| `format` | 固定 `epubox-document-1`；表示磁盘数据协议，与文档版本 2.3 分开 |
| `document_id`、`source_hash` | 文档身份、源 EPUB 字节哈希 |
| `resource` | 原包内路径、media_type、源资源字节 SHA-256；不取自译文 |
| `adapter_version`、`extractor_version` | 实际解析/提取协议版本，变化必须显式处理兼容性 |
| `source_markup` | 完整源 HTML/XHTML 字符串，含 head/body、标签、属性、代码和原空白；由原字节按既有 UTF-8 约定解码，不经过换行转换/strip；仅本地保留 |
| `nodes` | 源 node_key 到稳定源地址的表，以及 kind/qname；每次从未改动 source_markup 建树后解析，不对已改写树重新找旧位置 |
| `source_slots` | text/tail/白名单属性的源位置、源值/区间及唯一去向；空值无须创建模型任务但在源字符串中保留 |
| `units` | 每个 Unit 的完整源定义：ID/类型、源槽位、源投影、结构所有者/装配区域、固定语境、术语、适用检查、局部引用表 |
| `units[].registry` | g/x/b 的源节点/子树引用、父范围、边界/移动许可、源覆盖文字与 hints；冻结子树可指回 source_markup 中的 node_key，不必重复复制大代码块 |
| `boundaries`、`derived_bindings` | 源相邻关系/硬边界、导航等确定性派生的源绑定；不是可变译文依赖图 |
| `preparation_issues` | 明确的局部不支持或未决源问题，含作用域；不能静默删除对应源范围 |

**source_markup 是源结构的权威副本；其余解析字段是经过核对的派生计划。** 不能修改其中一份后继续信任另一份。BookPlan 记录每份 DocumentPlan 完整文件的哈希；模型调用前核对计划与原文的源位置/投影/保护关系。保存为 JSON 不会丢原始长属性，但长属性仍不得进入模型翻译请求。

源地址建议采用从文档根开始的元素子序号数组（明确不计注释/PI），并保存 qname 复核；适配器已有可靠地址方案可沿用。注释、PI、DOCTYPE、命名空间及混合内容仍由完整 source_markup 和既有安全解析器保留；装配器处理自己拥有的区域时不能丢掉这些本地保留对象。单位装配区域内存在这些节点时，源计划必须记录其模板/保护归属，不把“元素地址不计注释”误读为可以删除注释。

示意结构如下；其中具体哈希及完整节点/Unit 字段按上表生成，随包完整合成示例见 `examples/document.json`。此段仅展示职责，不作为可直接运行的完整计划：

```json
{
  "format": "epubox-document-1",
  "document_id": "d001",
  "resource": {"path": "OEBPS/chapter01.xhtml", "media_type": "application/xhtml+xml"},
  "source_markup": "<html xmlns=\"http://www.w3.org/1999/xhtml\"><head><title>Example</title></head><body><p>Hello.</p></body></html>",
  "nodes": [{"node_key": "n4", "element_path": [1, 0], "qname": "{http://www.w3.org/1999/xhtml}p"}],
  "source_slots": [{"slot_id": "s1", "node_key": "n4", "field": "text", "source_value": "Hello.", "owner_unit_id": "u001"}],
  "units": [{"unit_id": "u001", "kind": "paragraph", "source_projection": "Hello.", "slot_ids": ["s1"], "registry": {}}],
  "boundaries": [],
  "derived_bindings": [],
  "preparation_issues": []
}
```

这里保留 source_markup 不是继续让模型翻译 HTML。**请求构造器只允许读取 Unit 投影、必要 hints/constraints、语境和词条；不能把整个 DocumentPlan JSON 或 source_markup 发给模型。** 也不能只把 HTML 字符串套一层 JSON 而不保存 Unit/槽位/引用关系，再宣称已经完成解析持久化。

### 10.3 准备与持久化时点

1. 验证源 EPUB 和全局支持范围，建立只读 source.epub；按资源逐个解析、提取和核对。
2. 每份 DocumentPlan 写临时 JSON、flush/fsync、原子改名；重新加载 JSON，验证格式、源位置、投影和注册表可用。读完即可释放本章内存 DOM。
3. 初始化各 `units/<unit_id>.json`，把初始 CutPlan、pending 状态和额度写入；不等第一次成功才建立记录。无法可靠生成投影的已知局部源区域用 needs_attention 初始记录保留，cut_plan/input_hash 可为 null，禁止派发；它仍保有明确源归属，不能伪造空译文或空的可执行计划。
4. 所有必需资源均有完整文档记录/任务清单后，**最后原子提交 `bookplan.json`，其中 `preparation_state=ready`**，同时记录文档文件哈希和总必需源任务数。未能可靠生成投影的局部范围仍有归属和 needs_attention 初始记录，不能从清单删除；无法保证全书盘点完整则准备失败。
5. 只有 ready 计划存在并通过校验，才派发付费调用。之后每个响应、每个失败、每次校对/修订和每次派发预留都按 §9/§10.4 落盘。

准备中断且尚无 ready 的 bookplan 时，可以从源快照续做缺失的解析文件和初始记录；此时保证尚无模型调用，不涉及丢失已付费译文。已经 ready 的运行不得因缺记录而自动当作新任务/零计数，按 §10.5 隔离处理。支持按文档流式准备，不要求整本 DOM 常驻内存。

### 10.4 结果 JSON 与单写入器

UnitRecord 至少保存：`format=epubox-unit-1、unit_id、document_id、source_hash、logical_hash、input_hash、plan_epoch、record_version、revision、cut_plan、items、candidate、accepted_revision、accepted_target_hash、local_checks、review、unresolved_issues、counters`。

每个 items 记录对应当前 CutPlan 的稳定 segment/item 身份，包含阶段、状态、目标投影（未成功为 null）、目标哈希、检查状态、请求来源、失败原因和下一步动作。局部状态限定为 `pending / in_flight / candidate / local_valid / reviewed / retry_wait / needs_attention / blocked_dependency`；Unit 的 accepted 仍由 §8 汇总判定，不由模型直接填写。普通 Unit 使用一个 Segment 记录，不再维护另一套结果格式。

失败记录至少有 `scope、stage、code、message、request_id、item_id、plan_epoch、revision、retry_action`；retry_action 为 `automatic / explicit_retry / repair / dependency / none`。失败不能把原文写成 target，更不能将 target 非空等同成功。只读衔接/派生步骤的 dependency 状态写在 checks 或派生记录，不伪造翻译失败。

一个运行目录只有一个协调进程写入；网络任务把结果交回单写入器。完整 UnitRecord 同目录临时写、flush/fsync、原子替换；适用平台同步目录并测试。记录内部校验 `record_hash`（计算时排除该字段自身）；它用于发现损坏，不是抵御恶意手改的安全签名。加载仍须重新跑必要的结构/状态检查。[^R9]

对当前代次的 Segment 并发返回，协调器在最新记录上合并**当前 item**，再比较/推进 record_version；不能将含旧兄弟结果的整个对象覆盖回磁盘。持久化进度不增加目标 revision，不使正常兄弟响应过期。CutPlan 升级则将整个新计划和旧片段失效状态在同一 UnitRecord 中一次提交。

RequestManifest 的请求身份/wire_hash 派发后固定；其 attempts 数组按实际调用原子追加。每次 HTTP 派发前落盘 `attempt_id、affected_items、reservation、state`，随后才能发送；同一逻辑 request_id 的传输重试必须使用新的 attempt_id。计数恢复对 `(request_id, attempt_id)` 幂等合并，不能只按 request_id 去重而漏计真实重试。某个派发记录写好、Unit 预留尚未更新就崩溃时，恢复保守计入该预留，不能因此获得额外额度。反过来，只有本地预留而未确认发出的调用不宣称已计费。保留轻量计数/身份记录到运行结束，不必永久保存大响应正文。这是单机文件协议，不新增数据库或事件平台。

### 10.5 JSON 是正常续跑入口，不是可选缓存

正常恢复流程为：加载 ready 的 bookplan → 核验 source.epub 与 document JSON 哈希/版本 → 从 document JSON 恢复源 Unit/注册表 → 加载 UnitRecord → 按下表重新派发剩余工作。**不重新从原 EPUB 切整本书、不把最后成功序号当唯一断点，也不依赖退出前的内存 DOM。** 装配时可以重新解析 JSON 中的 source_markup；最终独立验证仍可读取源快照，这与不重新提取全部任务不矛盾。

| 已保存状态 | 恢复动作 |
|---|---|
| 当前版本 accepted 且校验有效 | 复用，不重新翻译/校对；必要的过期章节衔接仍重做 |
| 合法目标已保存、校对未完成或校对请求失败 | 复用目标，从校对继续，不重译源文 |
| 一个长 Unit 部分 Segment 成功、部分失败/未做，CutPlan 不变 | 复用成功片段，只补缺失/失败片段，再形成完整目标并校对 |
| pending 或中断遗留 in_flight | 核验请求身份与额度；in_flight 为远端结果未知，剩余额度内续跑，不假定未收费 |
| retry_wait 且自动额度未耗尽 | 按退避信息恢复；不阻塞其他 ready 项 |
| 自动重试耗尽、结构/语义 requires repair | 保留 needs_attention；继续其他工作。显式选择重试失败项/导入修订后再激活，必要额度提升必须记录 |
| blocked_dependency | 依赖当前已满足则入队；否则保留等待，不消耗请求、不永久占住 worker |
| CutPlan 主动升级 | 同 Unit 旧片段全部失效；其他 Unit 不变 |
| 单个 UnitRecord 缺失/损坏 | 隔离该 Unit 和其依赖，其他有效任务继续；不能重置已用额度或猜 accepted |
| 单个 DocumentPlan 缺失/哈希不符 | 隔离该文档及其依赖，其他已核验文档可继续；不在普通 resume 中静默重提取并混用旧译文 |
| 源快照/BookPlan 身份不符、共享盘点不可信 | 运行停止 failed，不用同名文件代替源书 |

恢复必须扫描完整任务清单以发现“中间的洞”：u001 成功、u002 失败、u003 成功，不能因为最后成功是 u003 就跳过 u002，也不能从 u002 起把 u003 重新翻译。自动额度仍足够的请求失败可以自动重试；已耗尽/需修复项只有显式授权才重开。显式授权追加新的尝试周期/额度，不清空历史计数或把所有失败项无差别再跑一遍。

损坏记录的恢复属于显式修复动作：能从已校验源快照/同版本适配器重建出与 BookPlan 登记哈希完全相同的 DocumentPlan 才恢复其源计划；否则新建运行。结果记录不能无证据重建成 accepted；未知计数由可信 RequestManifest 保守重建，证据不足则要求用户明确确认后追加额度。MVP 不建设自动历史迁移器。

旧 HTML checkpoint 不自动迁移到新协议，也不删除旧成果。**保留的是“EPUB 解析→JSON 保存→从 JSON 继续翻译”的产品流程，不承诺与未读取的旧 JSON 字段完全兼容。** 实施时读取实际 parser/schema/checkpoint，能复用的 JSON 写入与加载能力继续用；需要版本变更就显式隔离。旧运行可由旧引擎完成，不能把旧 translated_html 装进新 target 后标记成功。

### 10.6 完成率、失败与依赖报告

CLI/报告在执行时显示 `execution_state=running/draining/stopped`，结束后的 outcome 才取 §12 的四种值。运行过程中出现 needs_attention 的 Unit **不等于马上停止整个运行**。

至少分别显示：必需源任务数、成功接受数、有效派生数、待翻译数、待校对数、局部失败数、等待依赖数、当前阶段/在途数、累计请求和已知 token；按文档和阶段列出未决源位置及下一步动作。代码/合法保留内容另列，不作为模型失败项。完成率分子为当前已 accepted 的必需 Unit 加有效派生 Unit，分母为全部必需源任务。错误/等待/待做片段数另作非互斥诊断维度，不能相加当作总量；例如一个 Unit 可同时有失败片段和未尝试片段。

总必需数来自 BookPlan/DocumentPlan，不因失败、未知目标或派生等待而缩小。历史错误与当前未解决分开；JSON 结果存在/target 非空、尝试过、校对过、accepted 与全书 completed 是不同状态。report.json 是派生视图，损坏可重算，不能作为唯一状态来源。

## 11. 本地装配、导航、语言与资源

### 11.1 装配次序只有一个

```text
不可变源模板
  → 应用已接受 Unit 的目标事件流，恢复原始 g/x 对象
  → 消去虚拟 b 与切片边界，不新增真实结构
  → 建立源节点到目标节点映射（仅本地 sidecar）
  → 应用允许的属性、导航和元数据目标
  → 应用登记过的语言/既有排版变更
  → 序列化并重新读取验证
```

对一个源结构只有一个所有者：模板、某个重建区域或某个原子子树；不能祖先整块替换后再用旧 XPath 替换子孙。复制 x 时不带属于外层 Unit 的根 tail，内部 tail 按子树保留。

可译属性在恢复子树**之后**应用，避免 alt 被旧图片副本覆盖。冻结子树对比不是盲目比较整个旧哈希：先登记具体属性白名单变更，再核对其余数据/结构；不是把所有属性一概忽略。

模型文本用 XML API 作为文本写入，不重新解析为 HTML。保留命名空间的含义及依赖前缀的值，不因序列化自动重命名而破坏 epub:type 等值的解释。未修改的二进制资源逐字节复制；不重新压图、不删字体、不改资源路径。

### 11.2 独立最终检查

从源快照单独枚举文本归属与固定结构基线（这是最终独立验证，不是续跑时重新规划所有翻译任务）；从已验证目标事件流计算应有的许可变化；再读取实际输出比较。不能只相信装配器自报“已恢复了 N 个对象”，也不能把所有目标文字掩掉而漏检装配器吞字。

必须核对：每个源槽位有唯一去向、每个 Unit 被消费一次、目标文字等于其当前已接受译文、固定容器/列表/表格结构与顺序、g/x 身份与父关系、冻结内容、实际白名单属性值及内部引用。

输出树上的源对应关系可用本地 sidecar 辅助定位，但比较依据仍是源和目标实际内容/结构，不把 sidecar 声明本身当证明。验证应通过故意改 href、删节点、删中文字、重复 tail 等变异样本证明能够发现装配错误。

### 11.3 ID、URI 与导航

**ID 唯一性按资源文档判断，不是全书字符串全局唯一。** 不同章节都含 `id="section1"` 并不因此冲突。链接按源资源基址解析到规范化资源路径和 fragment；核验目标存在、引用不变，不去访问外部网址证明其在线可用。

支持的本地路径规范化、百分号编码、相对路径和同文件片段必须有测试。无法解析的特殊基址在预检报告，不到最后用模糊字符串替换。

导航标签和正文标题只有在目标绑定明确、源纯文本相同、目标无不适合导航的原子对象时，才复用标题的**文字投影**，不复制标题 DOM。此标签仍有自己的源槽位和 derived 状态，绑定标题的 accepted revision；标题修订后自动使派生值过期。源标签不同或复用不可靠则独立翻译/校对。NCX、head/title 和 OPF 纯文本字段使用同一规则，不把格式标记写入纯文本字段。

MVP 不实现跨书翻译记忆库。复用只发生在本次书的明确绑定，不能按相同词语给所有导航做全局替换。

### 11.4 语言与元数据的有限变更

目标主语言为 `zh-Hans`。更新对应 `dc:language` 及已翻译文档/元素的 lang/xml:lang；已明确保留的外语原文不被误声明为中文。原来继承英文语言的保留元素必要时显式维持其源语言；代码不因英语关键字自动标为自然语言英语。

没有真实元素承载的个别混合语言文字，不为标语言新增包裹节点；在报告中保留这种粒度限制。程序不能同时承诺“一个节点都不新增”与“任意混合句每个词都有独立语言属性”。

EPUB 3 更新包级 `dcterms:modified`，使用 UTC 格式，保持唯一的包级修改时间；EPUB 2 不硬塞 EPUB 3 元数据。原出版日期和作者等保持。[^R1] 需要更改的值进入 ChangeSet；其余元数据不由模型重写。

原出版物标识符保持，不在 MVP 重发 ISBN/标识符；源文件不覆盖、输出文件另存，字体混淆依赖保持。对可能依赖书名的 file-as 等派生元数据，不让陈旧值暗称已更新：按适配器确定性更新可处理项，其余保留并报告，不推导新的事实。

### 11.5 字体和排版

默认保留原字体与 CSS，关闭剪枝。仓库若已有通过真实样本验证的中文显示策略，可以作为**明确记录且可关闭的输出变更**复用；本次不假定它已经验证过。

不使用全局 `* { font-family: ... !important }` 覆盖代码、图标和公式，不内置或分发字体文件。排版策略只影响输出，不改翻译输入；策略变化后重新装配、做结构/资源和阅读验证，不必重译源义不变的文本。若策略改变了移动许可或内容含义，则不能按纯排版变化复用本次运行，应重新准备相关翻译计划。

## 12. 正式输出与故障恢复

### 12.1 唯一完成条件

只有以下全部为真才进入发布：输入/范围已通过；所有必需 Unit 当前版本 accepted，或由当前 accepted 标题可靠派生并通过文字/属性本地检查；没有未解决的阻断项；所有必需章节衔接检查绑定当前版本；最终结构和资源检查通过；最终 EPUBCheck 已执行并无 ERROR/FATAL。

WARN 和 minor 必须记录，但不自动等同于错误。真实阅读器抽查是**发布新引擎版本的验收项**；运行报告只报告本次实际做过的检查，不能让每本书必须有人手动确认才能获得机器完成状态，也不能每本自动写“阅读器已验证”。[^R4]

Run 的**结束结果**仅为 `completed / paused / needs_attention / failed`；正在执行时使用 §10.6 的 execution_state，不因一个 Unit 失败就提前结束。判定顺序：不可继续的全局输入/存储/内部/发布错误为 failed；运行级预算/取消/共享服务问题为 paused；其余可执行独立工作均已处理、本轮可自动重试也已终结后，仍有局部问题或其依赖则为 needs_attention；全部门槛通过才为 completed。局部问题即使与全局暂停并存，也必须保留在报告中。

**“没有输出正式 EPUB”不等于“失败后的章节没有继续翻译”。** 未决阶段的 JSON 已保存全部进展；补齐失败项并通过依赖检查后，直接使用已有有效结果装配。非 completed 都不能返回代表成功的退出码；实际退出码与现有 CLI 兼容映射。

建议 RunResult 字段：`status、output_path、output_sha256、structural_check、semantic_review、coherence_check、epubcheck、reader_check、unresolved_issues`。reader_check 未执行为 `not_run`。非 completed 的 output_path 为 null；工作目录路径单独提供。

### 12.2 输出提交步骤

1. 使用源与当前 accepted 结果在 staging 生成临时 EPUB；按源版本保留容器、manifest、spine、mimetype 等规则。
2. 关闭写入器，重开临时包；核验章节、资源、链接及规范，计算本次产物字节哈希。
3. 原子保存 `publish.json` 提交意图，包含 run/计划指纹、完整结果版本向量、目标路径、产物哈希和验证记录。
4. 在目标同一文件系统使用原子替换提交产物，再把 publish.json 标记完成并派生报告。
5. 返回本次真实产物；不通过路径存在就判断成功。输入路径、源快照路径和其符号/硬链接别名都不能作为输出。

默认不覆盖已存在的正式输出；用户明确允许覆盖时也必须先验证临时产物。运行间针对同一输出目标使用锁或独占提交策略，不能两个进程同时互相覆盖。

### 12.3 发布中断不能伪成功

若文件替换完成但状态尚未落盘，恢复时核对已保存的提交意图、目标哈希和当前版本向量，匹配才补记完成；不重新翻译。如果目标仍是旧文件、哈希不符或缺少可信意图，就不能把路径存在当作本次成功。

若验证、磁盘写入或提交失败，保留已接受译文及诊断，输出失败/未完成，不输出损坏 EPUB，也不删除原输入或之前正确产物。这里是文件级提交协议，不是引入数据库事务平台。

## 13. 对现有代码的最小改造路线

所有路径仍是待实际仓库核实的改造入口。保持 CLI 和可用 provider 接口，不为了重构统一搬目录。

| 原文件/职责 | MVP 修改 |
|---|---|
| `core/markup.py` | 统一解析/序列化、namespace 和混合空白处理；无模型 HTML 修复 |
| `epub/parser.py` | 保留包读取与现有 JSON 流程；强制导出完整 DocumentPlan JSON，提供 JSON 加载入口；结果状态交 store |
| `item/chunker.py` | 拆语义提取与传输规划；HTML 长度不再是请求单位 |
| `item/precode.py` | 复用有效保护规则，生成单次注册表；不在每次调用重识别 |
| `schemas/chunk.py` | 增加/迁移 Unit、CutPlan、UnitRecord；不借旧 translated_html 字段装新协议 |
| `agents/translator.py` | 保留模型接入，改输入输出投影和本地 RequestManifest |
| `agents/verifier.py` | 分开协议、结构、内容异常、源译审查；保留有效检测器 |
| `agents/workflow.py` | 实现固定校对/修订/衔接；局部错误转带 scope 的结果；依赖未齐挂起，不使后续工作 fail-fast |
| `agents/fallback_runtime.py` | 共用调度、请求额度、取消；不新增智能路由 |
| `services/glossary.py` | 用户词表、范围/模式和冻结；自动候选不作为前置必需能力 |
| `epub/replacer.py` | 从源模板和 accepted 事件流本地装配；属性后置更新 |
| `epub/builder.py` | 保留打包；关闭默认剪枝；验证、提交、失败返回统一 |
| `orchestrator.py` | ready JSON 准备门槛、全书非 fail-fast 调度、派生依赖、结束状态与发布门槛分离 |

确有需要再新增 `item/extractor.py、item/inline.py、item/planner.py、item/context.py、services/store.py`；CSS 有限扫描可放在 markup 附近的独立小模块。先拆职责再定文件，不建设庞大的插件/适配器框架。

### 13.1 开发闭环

**A：现有行为与最小样本。** 读真实调用关系，运行已有测试，保留发生过问题的源/目标小样本；只核对影响本次接口的现状，不要求先完结 68 项审计。

**B：无模型且跨进程往返。** 源提取 → 文档/初始状态 JSON 保存 → 退出并清空内存 → 仅加载 JSON 源计划 → 原投影原样返回 → 装配 → 打包重开。identity 模式不应用目标语言/书名等翻译收尾，按源结构语义核验，不要求 ZIP 时间戳或属性排列字节一致。

**C：完整单元主线。** 普通段落和常见内联先完成真实翻译、校对、保存、恢复及输出；注入中间 item/Unit 失败，证明后续同章和跨章内容继续、成功结果立即落盘、续跑只补缺项；长单元暂未实现时只能用于阶段样本，不宣称 MVP 已完成。

**D：长单元与边界。** 实现 CutPlan、虚拟边界、局部限额、原子升级、衔接复查和人工修订导入。验证 s2 失败不阻止 s3，普通续跑不使成功片段失效，并发片段结果互不覆盖。

**E：整书验收。** 覆盖导航、属性、语言、资源、发布恢复和选定阅读器；通过 §14 后新引擎才切默认。旧引擎保留用于旧运行恢复，不共享接受状态。

各阶段都保留可运行入口和新增回归用例；不先删除旧链路再开始设计，也不把 mock 协议测试当成真实翻译质量验收。

| T18 | 不同文档同名 ID、相对链接、非 spine 尾注 | 正确按文档解析；不误报全书 ID 冲突、不漏尾注 |
| T19 | 导航复用带格式标题、标题后续修订 | 导航只取有效文字；派生版本更新，不复制标签 |
| T20 | EPUB 2/3、字体混淆、签名/音频同步等支持边界 | 不误升级、不误判字体为正文 DRM；未支持关系预检指出 |
| T21 | 目标旧文件存在、写盘失败、替换后进程崩溃 | 不伪成功、不伤原书；提交意图可恢复确认 |
| T22 | 实书模型链路与目标阅读器 | 正文/代码/表格/脚注/导航可读；质量与成本有真实记录 |
| T23 | 同章中间 Unit 翻译失败，另一个 Unit 校对失败，并发分别设 1 和 2 | 同章后续与下一章继续并逐项保存；无 fail-fast，无静默缩分母 |
| T24 | s1 成功、s2 失败、s3 成功；进程退出后按原 CutPlan 续跑 | s1/s3 的目标复用，仅补 s2；Unit 齐备后才合并/接受 |
| T25 | 完整 Batch 一项缺失/无效，另一个 Batch 整体 JSON 截断 | 前者保存独立有效项；后者整批拒绝但其他批次继续，不抢救半截 JSON |
| T26 | 每份 HTML 解析为 JSON 后退出，重新加载并 identity/装配 | source_markup、Unit、槽位、g/x/b 与属性定位齐全；不用原内存 DOM，不把长属性送入模型 |
| T27 | 最后一项成功但中间失败；目标已生成而校对失败 | 扫描完整清单补洞；成功译文不重翻；校对失败仅续校对 |
| T28 | 一个 Unit 额度耗尽、章衔接额度耗尽，再分别触发运行总额度/鉴权/写盘失败 | 局部限额不停止独立任务；运行级限制才全局暂停/失败，错误计数不清零 |
| T29 | 失败标题使导航派生等待，失败段使衔接等待 | 等待不占 worker/额度；后续正文继续；补齐后只执行相应依赖检查 |
| T30 | 准备阶段中断、ready 后单个结果/文档 JSON 损坏 | ready 前零模型调用；ready 后不能把缺文件当零进度；局部可隔离则其他任务继续 |
| T31 | 同一目标代次两个 Segment 并发返回，一项先写错误或进度 | record_version 与 revision 分离；合法兄弟结果均保留，旧代次迟到结果仍拒绝 |
| T32 | 首个局部失败、所有 ready 任务排尽、仍有人工待处理依赖 | 不提前退出，也不永久等待；返回 needs_attention，output_path=null，全部进度可恢复 |

### 14.1 最小真实验收方式

选少量实际会翻译且有权使用的书，必须覆盖普通正文、技术代码、表格/脚注和复杂内联；若承诺 EPUB 2/3，两种包适配都须有样本。样本数量不替代内容覆盖。

针对这些样本保留一组固定源句，采用相同模型配置比较旧链路与新链路；人评分别检查忠实度、自然度、术语与格式归属，重点包含真实失败案例和结构合法的错译反例。没有数据不承诺“成功率 99%”或“成本下降一半”。

结构、源归属、资源引用、未决状态和发布伪成功这些确定性错误的验收目标为 0；语义质量通过真实源译抽查评估，不声称全书绝对零错。统计自动完成率和人工待处理比例，发现大面积锁序/拒绝就不能宣布产品可用。
