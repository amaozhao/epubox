# 移除输出长度限制

## 要求

所有新网络请求不发送 max_tokens、max_completion_tokens 或其他输出长度参数。新请求规划不因为估算输出超过旧 4096/8192 等数字而拒绝、拆分或缩小批次。CLI 不再提供输出长度选项。正文大小和输入预算继续按已有规则；完整响应校验、供应商截断识别、重试、单个失败后继续和有效初译复用继续保留。

HCI 三个实际失败请求都记录 actual output=8192、finish_reason=length；程序把请求输出预留当作接口输出上限发送，是当前可确认的原因。去掉程序参数并不能消除供应商自身的生成或上下文上限；供应商仍截断时不能把不完整响应作为成功回填。

## 兼容边界

旧 PreparationPlan、词表、成员、结果、预检和请求帧不因这次调整直接改写。旧预算版本继续按其历史规则验证，用于证明缓存译文和响应身份；历史数字不能限制新派发。

新预算策略使用版本 7，输出上限为空，输出 token 数仅作估算。请求 manifest 使用缺省时不序列化的 output_unlimited 标记，旧请求默认字段不改变原哈希。旧帧复核使用旧预算，新请求使用无输出上限预算。新实际请求的物理哈希以未设置输出参数为准，通过 attempt 的 output_unlimited 元数据与旧有明确上限的尝试区分。

已有完整预检和准备状态的恢复，只把未完成、可重新派发的请求切换到新策略，不删除成员或重做术语提取。初译成功的项只重新校对。旧截断响应仍是失败证据，重新派发沿用既有 retry/replay 关系，不重复接受旧的部分响应。

## 顺序

1. 接口与模型：移除所有实际输出参数和模型默认上限，保持多 key workflow、独立客户端和唯一 attempt 重试循环。
2. 预算与校验：新增无上限策略，输出估算不产生门禁，旧预算编码与验证结果保持不变；缓存与实际物理身份分别核对。
3. 调度：新初译、校对、术语及冲突解析使用无输出上限规划，旧准备批次可以重新合并；不改动已完成成果或回填身份。
4. CLI 与前期准备：删除输出配置入口，新书使用版本 7；兼容旧断点中保存的数字，不能重新引入限制。
5. 验证：真实保存响应诊断、请求参数断言、超出原 8192 的完整响应接受、旧/新及混合 attempt 重放、完整初译复用、供应商截断仍拒绝、真实 HCI 未完成队列预算与合并验证、全部回归和静态检查。

多 key 和准备并行已通过 1106 项全套测试，本次在其基础上继续实施，不撤销这些功能。普通文件继续使用单词命名，每个维护源码文件不超过 1000 行。

## 实施与验证

实际请求、模型工厂和 CLI 已不再设置输出长度上限，SDK 顶层与 extra_body 中的输出参数均移除。输出估算仅用于诊断，不再触发 output、context 或 TPM 长度门禁；新派发仍检查输入。历史完整缓存先验证身份再重放，新输入预测不会阻止合法缓存恢复。

原子正文与 legacy 翻译、校对、连贯性路径均已覆盖，术语提取和冲突解析不再按旧输出数字缩批。length 和 max_tokens 两种供应商截断标记统一处理，残缺响应不接受部分结果。旧未准备完成的预算通过五分片内部的逻辑 checks/output.json 升级，原预检、原子清单、用户词表及有效术语记录不覆盖；已准备正文继续验证原历史帧，新派发重新组装无上限请求。

独立代码复审发现并修复三处遗漏：正文 reserve 的间接输出 context 门禁、legacy 的输出拆批/拒绝、截断时接受部分结果。修复后的复审通过。新预算明确保存 output_limit=null，旧 v2–v6 编码及哈希继续验证。

真实 HCI 五分片断点临时副本恢复全部 15592 个成员，并选取本次日志三个失败请求的 19 个成员重新规划。结果合并为两个无上限请求，正文分别为 2756、1510 tokens，输出估算分别为 9810、5004 tokens；完整请求及回填关系复核通过，超过旧 8192 的估算不再拦截。验证耗时约 106.5 秒，无网络调用，只写临时副本。

供应商自身仍可能截断，程序保留明确失败及重试处理；不把残缺响应或未翻译原文用于补齐最终书籍。

最终全套测试 1145 项通过（319.66 秒）；Ruff、格式、Pyright、差异检查及文件命名/1000 行约束通过。复审新增的 legacy 输出门禁、截断部分接受和正文 reserve 间接限制均已修复并覆盖测试。
